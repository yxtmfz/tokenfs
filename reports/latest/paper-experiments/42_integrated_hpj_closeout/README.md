# TokenFS：三个创新点与整体性能的统一小规模结果

**当前结论：本轮修改和完整小规模复核已完成，但“所有场景、所有指标均提高”的目标未达到，不能据此宣布实验结束或稳定全面优于SIEVE。**

最终候选使用同一个二进制，对三种固定输入、五个版本各跑正反两种顺序，共30次测速、17,280次请求；每次576×2MiB。此前本轮另有15次带探针诊断、30次候选测速，全部保留在37–39号报告，没有只挑最后获胜的运行。最终另做5组、480次逐请求SHA256校验，校验耗时不计入性能表。

Full是H/P/J全部开启；H对照仅关闭最终时变价值（StaticValue），P对照仅允许请求者域放置（CallerOnly），J对照不扣受害者价值和不确定性（Independent）；整体对照是等能力共享SIEVE1。各消融保持其余开关、缓存总量24MiB、在途缓冲4MiB、输入和二进制一致。四组表复用同一次Full，不能分别挑选不同获胜运行。速率由实际请求字节除以完整墙钟计算，包含前台控制开销。

表中MiB/s为两次总字节/总墙钟；p99为两次全部请求合并后的描述值，不是置信区间。排空吞吐还计入后台任务完成等待。严格复测通过要求两种顺序**各自**速度>0、p99不增加、排空吞吐不下降且消融机制确实改变动作；没有5%门槛。

## 本次实际修复

1. 重新建立H/P/J的单开关条件消融。旧热点重置开关仍影响短窗口衰减，但不能完整移除新增长周期重访与突发估值，所以不能继续用它代表当前全部时变价值。
2. 将布局锁内的辅助后台计数改为缓冲批写，SQLite事务内重复SQL只prepare一次；给刷新过程增加串行完成约束，保证后台完成计数不能越过尚未落库的统计。相同修复应用所有版本，保留FULL-WAL以及缓存READY状态的持久化语义。回滚、计数落库顺序及真实复制的原生测试通过。
3. 对出现跨突发重访的新需求，降低长期未重访旧对象的历史价值；再用实际时间聚集性限制该衰减，避免把均匀随机重访当成热点迁移。估值仍对到达对象和驻留对象对称，无输入名称、未来访问或真实阶段边界进入决策。新规则是启发式，不是理论最优证明。

## 为什么还不能宣布全面成功

固定热点的有效热点集能够容纳于总缓存中，Full与SIEVE的复制次数接近，算法额外开销和短测试环境波动足以影响几个百分点的差异。不能把某一次小幅正数写成稳定算法优势。

移动热点里，联合准入减少了复制及部分远端读取，但独立准入也获得了更多复制期间的在途内存读取。内存读取比磁盘读取快；当前收益模型主要估计远端与本地磁盘差额、复制成本和被淘汰价值，对这一临时内存收益尚未闭合。这是联合机制的剩余建模缺口，不能以“少复制”替代真实速度，也不能通过禁止对照的相同缓冲能力制造胜利。该解释受到服务路径计数支持，但尚未通过单独干预证明全部因果。

均匀随机输入没有稳定的消费者热点分工，亲和不应被预设为必然获益；它是回归对照，必须保留负数。当前一些p99变化还跨零，小规模数据无法支持“每个指标稳定提高”。

## 论文能写到哪里，下一步最小必要工作

可以写方法、实现、消融设计，以及这些指定开发负载上的实际增益与边界。现在不能写“全面、稳定优于SIEVE”，不能把三个开关各自在部分场景有增益等同于三个创新点都充分证实；条件消融也没有证明完整H×P交互效应。

剩余技术优先级是：先对联合控制中的临时内存服务收益进行逐请求归因，并在等内存预算、等共享能力下校准收益估计；新修改只有通过整个H/P/J矩阵才进入候选。随后用一个事先冻结、未用于调参的短输入检查泛化，而非继续在同一组种子上反复跑到获胜。无需先扩大到数百次。

当前是cn7上的三个串行逻辑缓存域，经已有cn13 NVMe/TCP存储，未使用cn14；没有物理多GPU、NVLink/PCIe或真实LLM推理测速。因此P目前支持的是跨逻辑域缓存放置的条件收益，不能当作物理GPU亲和或共享KV端到端加速的证据。论文若保留物理GPU主张，需要对应实验；否则应收缩表述。三个创新点的独创性也不由性能表自动保证。
