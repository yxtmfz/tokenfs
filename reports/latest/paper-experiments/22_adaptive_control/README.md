## 这次修改了什么

1. **有限空闲容量探索**：首次访问可使用真实空闲空间提前缓存，不淘汰任何对象。若测得的校验复制成本超过一次远端读取，则停止该探索。首次成本未知允许填充；这是有界探索，不伪称每次都有已证实的正收益。每组实际探索12次，即12个2MiB槽。
2. **按照观测到的时间相关性调整衰减**：将相邻同对象访问概率与窗口内随机碰撞概率比较。类似独立随机的间隔不再被误判为旧热点迅速失效；有连续复用证据时仍保持响应。运行时没有场景、种子、阶段和未来请求信息。
3. **替换风险余量**：复用时间规律弱时，将计数波动余量加入淘汰损失，避免仅因随机频次差就搬运数据。准入、位置选择和最终提交计费一致。这是启发式余量，不是统计置信区间或已证明的最优策略。
4. **缩短建议规划持锁阶段**：驻留/容量快照仍在锁内取得，目的地计算和建议事件记录在锁外完成；执行淘汰前重新锁定并校验当前状态。测试特意在建议计划后加入未知文件，确认不会信任过期的空闲容量。
5. **共同计量**：全部三种策略都开启Open耗时和布局锁等待计量，保留相同持久性、复制校验和I/O方式。新策略默认关闭；新增配置有适用范围检查。

## 机制证据及仍未解释的部分

随机场景新版复制58.67MiB，对照SIEVE-1hit为566MiB、SIEVE-2hit为540.67MiB。CPU时间3.62秒，对照分别6.23秒、6.00秒。每个随机种子只有24–33次复制，风险余量在788–891个候选计划中生效；这证实反复替换确实减少，不能只拿一个未执行的预测分数当证据。

但远端读取仍为596.67MiB，SIEVE-1hit为576MiB、SIEVE-2hit为594MiB；节省复制和CPU不保证每个有限随机样本都更快。种子3212的较大优势不能外推为普遍优势。与报告21使用不同种子、日期和共同计量，不能跨轮相减声称本次修改的严格因果增益；本轮未加入同期旧版对照。

热点场景风险余量未额外收费（0次），保持了突发复用响应；新版远端读取242.67MiB，SIEVE-1hit为258.67MiB。总速度优势仅0.81%，说明节省流量尚不足以形成显著余量，三个H/P/J组件也需要新版本下单独重验证。

## 实验边界与审计

- 18次测速：三种策略×两个未改变的场景生成器×三个新种子。热点3201–3203，随机3211–3213；六组96请求内容检查3199/3198。每个场景中各策略轮流占据三个执行位置。冻结后无调参、追加或替换测速。
- 总缓存24MiB，新版8/8/8MiB，SIEVE池化24/0/0MiB。它们是整体竞争力对照，非相同分区约束的单开关消融。不能用改变基线容量来得到优势。
- 同一Release程序、同种子输入、相同直接前台I/O、异步校验复制、空应用缓存、FULL-WAL持久化。cn7→既有cn13 NVMe/TCP，未使用cn14。目标页缓存未受控清空；三个逻辑消费者串行，同一客户端磁盘，不是物理多GPU推理。
- 83项Python测试、3项C++测试、六组全请求SHA校验通过。全部18组输入、字节守恒、配置、容量、时间线、后台收尾、逐消费者/对象计数、访问顺序及源代码/二进制哈希通过独立复核。故意修改字节、配额、时间线和数据库计数均被拒绝。
- 小样本不证明统计显著性、所有负载优越或三项独立研究创新。新版本没有同期旧版及H/P/J关闭组，旧轮次百分比不能直接挪给新版。严格门槛保留在development/closure-gates.json，全部三个闭合值仍为false。
