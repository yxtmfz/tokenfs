# Report69 — 热点改进方向验证

**选择：保留容量感知规划剪枝作为后续开发候选，不采纳简单驻留窗口缩放。创新1尚未闭环，未扩大或补跑本轮实验。**

完成12次cn7→cn13 NVMe/TCP测速、13,824次计时请求和480次独立内容校验。四张完整表及新旧版对照见 [tables.md](tables.md)。两个输入均曾用于开发，每个配置只运行一次。本轮是方向筛选，不能替代报告66独立验证，不能将本轮正向结果写成稳定或显著提升。

## 两个方向与实际改动

方向A在本地模型中限制热点预测的驻留窗口，八输入32个模型臂未呈现足够机制优势，完整负结果与可复现源码在 [direction-a](direction-a/README.md)。没有把模型计数转写成服务器速率。

方向B没有修改热点估值公式。旧规划预检假设空缓存，真实缓存已满时仍可能进入“空闲空间探索”，失去廉价拒绝的作用。现在先读取真实用量，用忽略非负受害者损失的乐观界判断；只有可能获益的位置才构造驻留快照和做完整规划。真正复制仍使用完整准入，并检查实时容量、pin和价值。对于相同政策状态，完整规划允许的操作不得被乐观界拒绝；这不保证异步执行的动作序列逐位相同。

生产改动只有 src/main.cpp 与 src/measured_policy.h，适用于本次全部 measured 策略臂。没有改变NoHotspot基础频率对照、SIEVE能力、容量、输入、正确性或持久化要求。该修复属于共享工程路径，不能当作创新1的新算法贡献。

## 机制证据及未解决问题

- 公开Full跳过771次快照、剪掉2325个候选位置，实际快照147次，旧Full为920次。无效规划减少有直接计数证据；新旧版吞吐只差0.272%，不可仅据此宣称稳定提速。
- 移动Full只跳过1次快照、剪掉11个位置，新旧快照140/138次。新版CPU为2.46秒，旧版3.04秒，但远端读取146/144 MiB、复制68/66次。新旧动作不同，单次顺序和运行波动未排除，不能把7.796%的增益全部归因于跳过快照。
- 移动H消融中新Full远端146 MiB、复制68次，NoHotspot为158 MiB、28次。本轮端到端收益为正，但复制仍明显更多，重现性尚未建立。
- 公开H消融中新Full远端1754 MiB、复制40次，NoHotspot为1748 MiB、28次。更多复制没有换来更少远端读，说明估值/受害者选择的净效益问题仍在。执行层减负并未解决这个缺口。
- NoHotspot保留近期基础频率、读成本、复制成本、放置及联合准入；本次消融检验动态估值增强的边际收益。不能通过削弱对照获得正结果。

## 方向选择与论文收口条件

本轮足以选择“保留规划减负候选，继续诊断热点估值的无效迁移”这一方向，不足以完成全部论文主张。方向A不推进至服务器；方向B留在研究分支，独立已验证版本仍为报告66原冻结版。公开回放是必须报告的H反例，不能删去或与移动结果平均后隐藏。

下一步先按实际服务层、历史复用间隔、已执行迁移及受害者后续读取，诊断公开回放的12次额外复制是否兑现收益。后续信息只能用于离线诊断，线上决策仅用已观察前缀；没有证据前不再盲目提高热度或降低迁移门槛。若继续修改H，必须冻结新实现后重做完整单开关消融，不能沿用本轮P/J数值作为新版本证明。若将H主张收紧到移动热点，则公开回放退化应写为适用边界，仍需预先固定、均衡顺序的小规模确认，不得只对失败项重跑。
