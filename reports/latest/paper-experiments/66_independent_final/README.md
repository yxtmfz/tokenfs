## 最终结论及可写入论文的主张

本轮完成34次固定版本独立测速及480条独立内容校验；数据完整性通过，**性能目标没有全部达到：严格条件18/26通过**。不再追加筛选或优化后复用本批为独立数据。

- 整体方案：公开轨迹3/3吞吐和p99均改善，合并吞吐+20.503%，每窗口p99降低9.298%–9.702%。移动热点合并仅+0.251%，2/3更快，不能称稳定优势。固定热点+3.771%、均匀随机+12.856%各只是一项边界观察。
- 逻辑域放置：移动/公开吞吐分别+6.507%/+2.405%；正向输入2/3和3/3，严格双指标均2/3。支持当前逻辑域环境下的有限边际收益，不支持所有输入/尾延迟都改善，更不支持物理GPU结论。
- 联合准入：移动/公开吞吐分别+7.791%/+5.456%，两类均3/3吞吐正向；严格双指标2/3和3/3。可写为受害缓存损失感知准入的边际效益；NoJoint不是通用独立H+P控制器，所以不能写全局最优或超加性。
- 热点估值：移动吞吐−0.511%，只有1/3更快；公开+0.505%，2/3更快，严格条件两类均1/3。未确认独立性能贡献；不能以报告64旧输入的正结果覆盖本次结果，也不能把约0.5%的混合方向变化写成稳定提速。

建议实验章节以公开访问轨迹上的完整存储收益为主，保留逻辑域放置与损失感知准入的消融证据，将热点估值作为仍有代价权衡的组件呈现。三个模块不自动等于三个学术创新；本批不能证明三项均稳定提升，也不能承诺投稿级别或统计显著性。

## 机制与开销解释

移动热点三输入合计：Full相对NoHotspot远端读取从486降至436MiB，但缓存复制从168增至398MiB、daemon CPU从8.56增至9.24s。真实速率反而从345.661降至343.894MiB/s。这些计数与额外复制/控制成本抵消读流量收益一致；仅凭计数不能完全分解每项因果耗时。新种子和更长回放同时变化，因此也不能断言未复现仅由其中某一个因素导致。

公开三窗口合计：Full与共享SIEVE的远端逻辑读取为5284/6430MiB（减少17.823%），缓存复制逻辑字节为210/6430MiB（减少96.734%），daemon CPU为15.47/32.96s。Full与NoJoint复制为210/958MiB，远端读取为5284/5616MiB。这支持减少无效缓存搬运的机制解释。上述是逻辑I/O与进程CPU计数，不是实测网卡流量、物理磁盘写放大或完整因果分解。

## 固定环境与论文边界

cn7为单客户端，cn13为真实NVMe/TCP远端；3个逻辑消费域串行回放，共享主机磁盘，不是物理GPU并行。每次1152×2MiB请求，24MiB磁盘缓存与4MiB共享捕获内存。所有版本共享同一执行优化、直接前台I/O和复制校验；cn13系统缓存未控制，未调整共享服务器环境。

三个移动输入为73501–73503；公开输入为73601–73603。公开Mooncake轨迹保持原块标识与顺序，统一为2MiB随机有效载荷，以源请求序号模3构造逻辑调用域，饱和串行回放，不能解释为真实模型KV字节、真实GPU身份或端到端推理性能。固定热点与随机各只有一个边界输入，未对它们进行三项消融，不作稳定性结论。

NoJoint只关闭现有受害缓存损失感知的准入项。这一消融只识别其边际作用，不能推出完整控制器优于所有独立H+P组合、全局最优或超加性。共同的元数据与复制路径优化不能算作三个策略模块的新贡献。SIEVE是TokenFS中的等能力算法适配，非原生SIEVE系统的端到端对比。

运行级完整数据见raw/cn7-evidence.tar.gz；严格比较见comparisons.json；各模块复制、远端读取、CPU、RSS和排空性能见final-summary.json。内容校验单独计时，不混入速度结果。所有零收益、负收益和未触发项均为最终结果的一部分。
