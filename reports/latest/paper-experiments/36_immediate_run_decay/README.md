# 热点遗忘与退出迟滞修复：最终小规模结果

本次定位并修复两条估值路径：①短请求窗口删除较早突发后，持续热点价值被压至零；②独立重访摘要采用宽限期，又让热点改变后的旧对象退出过慢。第一版保留容量有界的重访摘要；第二版从最后一次观察起立即衰减，使用已测重访间隔作半衰期。新旧对象对称估值，单次突发不获持续加成，不读取场景标签或未来请求。两个选项默认关闭，仍在草稿PR中。

先完成18次第一版对照，发现移动输入退化后，以第二版固定做12次针对性对照，总计30次、17280次请求；没有增加新种子或事后剔除运行。本报告完整保留两个候选的结果，第二批是诊断后的开发修复验证，不是独立确认集。

## 第一版证据与修正依据

第一批报告35：两条固定热点的误淘汰从原策略每次4、8次降到0，复制从34、48降到30、41，与SIEVE相同。固定3271速度仍有正有负，不能称稳定胜出；固定3291相对SIEVE两次提高3.35%、4.00%。但移动3293第一版157.48 MiB/s、原策略170.53 MiB/s，退化7.65%；远端流量158对98MiB。分阶段速度为第一版167.87/160.95/145.35，对照168.93/174.49/168.32 MiB/s，回退集中于热点切换之后。保留完整报告35及原始日志，未用第二批覆盖第一批。第二批GraceFull保留第一版行为，Full仅改变宽限期，避免混合更改后无法解释。

## 仍未闭环的缺口

移动输入对SIEVE仍慢1.984%，排空后同样慢1.985%。Full远端读取112MiB，SIEVE114MiB；Full CPU为2.70秒，SIEVE2.40秒，复制55对53次。因此剩余差距不能简单解释为远端读取更多。控制器、布局决策和复制路径开销是下一项待隔离验证的假设，当前未开启细粒度计时，不能把CPU差值直接当作策略规划耗时。

第二版对第一版的两个固定热点执行动作序列完全相同，尽管速率有正差，不能把这部分提速单独归因于取消宽限期。移动输入的动作确有改变，远端读取148→112MiB，前台提高5.61%、p99降低5.62%，支持退出迟滞得到缓解。随机输入相对第一版p99仍增加0.60%，固定3291相对第一版p99增加7.27%；不能忽略这些未通过项。固定热点没有误淘汰这一机制结果已重现，但最新速度仅n=1，需要后续有限重复才能谈稳定优势。
