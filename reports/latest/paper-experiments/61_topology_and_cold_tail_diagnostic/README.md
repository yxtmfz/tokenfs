# 物理拓扑核验与首次读取尾延迟诊断

用户将验收明确为两轮四项吞吐严格提高且 p99 严格降低，并在硬件核验后明确继续 cn7 的逻辑 GPU 域小规模验证。报告60按这个标准为5/8项通过，总体未通过。历史报告不改写。

|主机|本次可见设备及链路|实验角色|
|---|---|---|
|cn7 / 28.10.10.7|仅 Matrox 管理显示控制器；无 NVIDIA 设备或计算 GPU；/dev/nvme1n1 为指向 cn13:4420 的 NVMe/TCP|报告60与本诊断的唯一客户端，3个串行逻辑消费域|
|cn8 / 28.10.10.8|仅 Matrox 管理显示控制器；无计算 GPU；本次未挂载 NVMe设备|未参与本批实验|
|cn13 / 28.10.10.13|本地 PCIe NVMe 存储设备|远端存储目标|

结论是当前系统可见范围内没有可供本实验使用的计算 GPU，不能仅凭两个物理 IP 将逻辑消费域结果称为物理多 GPU 实验。未访问 cn14、未安装驱动、未改变挂载。各主机系统墙钟存在偏差，诊断时间关联只使用 cn7 的单机单调时钟。

## 诊断设计与结果

沿用报告60冻结的同一二进制、源码和 moving3293 输入，Full 与共享 SIEVE 各一组，576条2MiB请求。只打开请求分段遥测；两组均为诊断，不作为新的性能比较结果。保留全部请求和事件，独立重算通过。

|每组最慢6次请求的均值|Full|共享 SIEVE|
|---|---:|---:|
|客户端响应 ms|28.829|28.395|
|客户端打开 ms|3.895|3.363|
|守护进程打开 ms|3.372|2.825|
|实际 pread ms|21.161|21.137|
|布局锁等待 ms|0.00217|0.00212|
|与后台复制重叠 ms|0.078|0.152|

上述12次最慢请求均为真实远端读取。报告60中 Full 两轮最慢各6次全部是对象首次访问。减少重复远端访问能提高吞吐，但不会自动加快这些冷读。此诊断不支持把布局锁或复制重叠直接认定为主要原因，阶段差值也不是随机化因果效应。

源代码另确认首次打开先单独 Upsert 文件元数据，再单独提交读取计数；拟将其合并为一个 FULL-WAL 原子事务，对所有版本一视同仁，保留回滚和持久性。需要新完整矩阵验证，不能用本诊断声称已修复 p99。

新 acceptance_v3 判据要求每项 gain_pct>0、p99_change_pct<0，并保留排空吞吐和机制检查；八项完整且全部通过才可报告成功，持平不通过。首次注册失败回滚、旧注册拒绝覆盖、持久化重开和严格判据有独立回归测试。
