# Batch 79 independent protocol review

This is a pre-execution protocol/verifier review, not performance evidence. No server access was used. The frozen source archive contains exactly 350 files and matches `source-hashes.json`; archive SHA-256 is `623debd261469ae7377c6072ceb3333f425abf2014bb686f4b153a56f16ffb65`.

`preaudit79.py` passed 18 directed validation checks and the 6 targeted frozen Python tests. `preaudit-review.json` records the checks, the four reversed execution orders, single-component policy differences, and verifier/tool hashes.

- The 24 speed cases require CPU set `[0,2,4,6]` in both before/after environment receipts. The independent verifier checks all 48 receipts and serial run ordering in addition to the frozen source audit. A wrong CPU in either phase is rejected. The daemon and workers inherit the speed-driver affinity on Linux; no claim of a live per-thread CPU receipt is made. Four distinct cores on one socket reduce placement variability but do not fix frequency or provide exclusive cores. Batch 78 was not pinned, so 78/79 times are not a controlled causal comparison.
- Full/NoHotspot/NoAffinity/NoJoint speed cases must have active precheck initialization and positive attempts/rejections. PoolSIEVE1 and NoSubmitPrecheck must have zero activity. Counts require `0 <= rejected <= attempts`. The short correctness sweep requires successful initialization where enabled but allows zero attempts/rejections; a 96-request prefix need not exercise every mechanism. This avoids rejecting legitimate short/partial content tests.
- NoSubmitPrecheck changes exactly `precheck_shared_submission`. It retains the common tail buffer, RAM routing, object prior, deferred telemetry, and release fence. The implementation comparison stays separate from the 16 main H/P/J/SIEVE gates; changed policy actions are not required for its acceptance. The precheck may reject now where a queued task would reconsider later, so unchanged admission formulas do not imply identical action sequences.
- Every arm requires `read_release_count == read_open_count == request count` plus submitted/completed equality in the drain snapshot. Final counters after daemon shutdown must remain unchanged. The collector preserves absent or complete zero-byte-WAL/32-KiB-SHM bundles, checks SQL immutably, and verifies every SQL file is copied unchanged. It does not delete sidecars or silently omit pending WAL data.
- Directed mutations reject wrong NoSubmitPrecheck configuration, wrong before/after CPU sets, overlap, inactive-arm activity, missing initialization, and impossible counters. A clearly labeled synthetic gate fixture confirms that positive aggregate means cannot hide a failing second round. No synthetic times are published as experiment results.

The 163-test frozen-source/standalone logs contain fixture content-driver printouts. Those are local test output, not real server content checks. Only the later server `correctness/` evidence with six cases, 576 request SHA checks, source/binary/config receipts, and independent audit may establish that result. The real batch must still pass its own evidence audit before any performance or correctness conclusion is reported.
