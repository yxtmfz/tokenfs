## 发现的两个缺陷

1. 成本估计把FUSE拆分回调的每字节耗时等权更新。报告23记录的真实拆分包括1048528+48字节，48字节固定调用开销被放大；本报告首次SHARED_PLACE的2MiB复制成本先验达1.45–1.57秒。原生反例进一步重现“完整本地读取更快却被旧估计判成更慢”。这证明计量方法有缺陷，不证明第二种子的全部损失只由该缺陷造成。其848MiB前台远端读取、20次复制和大量拒绝准入值得与修正版对照。
2. 结果快照可能早于末次后台决策指标刷出。本报告3232/AdaptiveHP-fill的7项决策统计在result.json中略低于最终SQLite，如shared_placement_no_gain为383而数据库为384。原始文件均保留。吞吐计时、读字节、请求数、复制数、后台完成数、容量和内容校验一致；但严格“全部指标等于最终数据库”检查失败。validation/independent-review.json明确passed=false、critical_checks_passed=true，并列出全部差异。不能宣称本报告所有审计全通过。
