# 时间对齐与剩余复用：18 次小规模实测

**热点 +5.59%、亲和 +7.34%、联合控制 +4.15%，三种比较均为3/3种子提速；完整版本相对基础共享 +14.31%。热点与亲和通过本轮5%先导门槛，联合控制尚未通过；完整版本相对同容量共享SIEVE仍为 −1.84%。因此已有实测进展，但“全部明显领先强对照”的目标尚未完成。**

本轮修改了实际 C++ 策略，在 cn7 经既有 NVMe/TCP 完成 **18 次测速、6 组逐请求内容检查**。本轮所有策略使用同一 Release 二进制，先冻结代码与三个新种子，再运行。以下全部速率来自实际读取字节除以完整前台墙钟耗时。

## 改了什么，为什么这样改

1. **统一时间尺度。** 所有消费者只保留全局最近128次请求内的证据。无亲和时只取该域在同一窗口内的请求；有亲和时汇总所有消费者。因此不活跃域不会用很久以前的热门记录保护过期副本。
2. **热点剩余收益。** H不再仅凭连续miss截断历史。在新实验模式中，用对象历史平均复用间隔设定衰减半衰期；超过预期间隔仍未再次使用的对象，其保留收益下降。迁入和驻留使用同一公式，避免人为压低受害对象或单独放大迁入对象。
3. **共享亲和。** 使用所有近期消费者的需求给副本估值，在各域配额内选址；仍有另一份可读副本时，不把淘汰冗余副本计为丢失全部共享收益。保留在途复制合并和提交前重检。
4. **联合决策与规划成本。** 迁入收益减去真实采样复制成本和受害对象的剩余共享收益。空缓存都不值得复制时提前拒绝；已经找到零损失目的地时停止重复扫描。这些规划优化在本轮所有新measured组都开启，组件比较不混入不同实现优化开关。

用n表示同一窗口内的观测次数，age表示距最后一次观测经过的全局请求数：

`h = max(4, (last − first)/(n − 1))`，仅n≥2时使用；

`U(x) = max(n−1,0) × 2^(−age/h) × bytes × max(remote_cost−local_cost,0)`；

H关闭时衰减因子为1。P开启时n与间隔来自所有消费者，关闭时来自对应域。J选择正净收益最大的可行位置；关闭J只去掉受害损失在准入和选址中的计费，仍保留淘汰排序和配额约束。4请求下限是明确的启发式，本轮未证明参数最优。

旧策略及默认配置保持不变，新机制由`measured_causal_window`显式启用。在此模式下，原`measured_shift_reset`开关控制剩余收益机制，所以H的旧reset计数应为0；实际生效通过新折扣计数及动作差异核对。

## 为什么联合控制转正，整体仍略落后强基线

同版本、同种子对照中，HP相对Independent把远端读取从374.00降至297.33MiB（−20.50%），复制从130降至92MiB（−29.23%），CPU从4.593降至4.413秒（−3.92%），完整前台时间减少0.436秒，配对速率提高4.15%。这次节约复制没有以更多前台远端读取为代价，方向与上一轮相反。新旧轮次种子不同，不把它写成修改代码直接产生了某个跨批次百分比。

相对PoolSIEVE2，HP远端少读14MiB、少复制4.67MiB，但CPU多0.317秒，前台仍慢0.196秒。输入/输出与CPU有重叠，这不是严格的耗时因果分解；它指出重复元数据查询、候选扫描和控制开销是下一步值得剖析的成本。当前不能宣称亲和机制已超过简单共享池。

另外，HP的平均请求p99为40.95ms，高于Independent的37.03ms和PoolSIEVE2的36.16ms。吞吐改善不能写成尾延迟也改善。四格交互项平均仅−0.046秒，不足以声称显著超加性。

## 可复查性与边界

- 74项Python测试、3项C++测试通过。18次测速及6组逐请求SHA校验分别审计；每次缓存配额、真实字节计账、前后台结束状态、请求时间线均校验。另从原始请求与结果重新计算全部汇总、配对提升和交互项。
- 6策略×3新种子2901–2903；单个针对性合成场景。三阶段热点移动、主消费者变化、四请求突发。不是生产KV轨迹；没有把前轮种子或逐请求哈希验证的耗时混入速度结果。
- 每组输入、字节数、O_DIRECT、异步复制和校验路径相同。前五组各域8MiB，共24MiB；PoolSIEVE2为共享24MiB、其他域0，保留这个强对照。目标机页缓存没有受控清空。
- 仍是同一客户端上的3个逻辑缓存域、串行请求和真实远端存储。未测CUDA、NVLink或真实GPU推理，不能将本结果写为物理多GPU推理提速。
- 上一轮所有负结果完整保留；新旧批次种子、代码不同，不能将两个批次均值直接解释为本次改代码带来的因果提升。

## 创新性与论文主张

本轮形成的是三个可消融的候选机制，创新性需要和已有工作具体区分。访问频率与时间间隔估计已有[LUV](https://www.usenix.org/conference/usits-99/using-full-reference-history-efficient-document-replacement-web-caches)等研究；成本驱动共享缓存、迁移和复制已有[TPDS 2019](https://grc.iit.edu/publications/wang-2019-cost-driven-f3e9/)研究。不能把指数衰减、共享副本或成本函数单独宣称首次提出。

论文更合理的候选贡献是：**变化需求下，以统一时间尺度的消费者证据，估计共享覆盖的剩余收益，并一致用于准入、选址、淘汰和提交前重检。** 本轮只筛选其实际可行性；尚不构成中科院分区或三个独立创新点获认可的保证。详见`provenance/novelty-boundary.md`。
