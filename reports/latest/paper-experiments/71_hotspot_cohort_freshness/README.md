# 创新1专项诊断：热点经验新鲜度候选（报告71）

**结论：候选未采用，生产策略恢复报告70版本。** 本轮做了有针对性的实现修正与12次真实测速；公开回放吞吐改善，但移动热点仍慢于基础频率消融，p99也没有两轮一致降低。不能把“新版比旧版的汇总值略好”写成“创新1已经验证成功”。[全部表格及逐轮结果](tables.md)保留正负结果。[报告70四张表](../70_final_confirmation/tables.md)完全不变，仍是现有正式确认依据。

## 为什么基础策略有效，创新1消融仍可能不佳

NoHotspot并非没有热点判断。它保留近期访问频率、成本核算、跨逻辑域放置和联合准入，只关闭新增的动态估值。因此本消融回答的是“动态预测是否比基础频率多带来实际收益”，并不否定缓存或热点判断是系统基础。

被预测会再次访问的数据不一定值得搬到磁盘缓存：一些连续重复已由4MiB共享捕获服务；复制、校验、元数据与淘汰占用真实时间；短暂或陈旧的重复经验也可能触发无法回本的搬运。代码已有相关折算和成本项，但现有结果表明估值与实际可兑现收益仍有偏差。命中增加、复制减少、理论构成完整，都不能单独证明端到端更快。

本轮移动热点两轮合计，候选相对NoHotspot仅少读18MiB远端数据（318/336MiB），却多复制152MiB（132/56次，每次2MiB），CPU多0.67秒（6.34/5.67秒）。这些计数与吞吐下降的解释一致，但不是各项耗时的精确因果分解。冷读与尾部请求仍纳入p99，不能删掉它们制造提升。

## 本次尝试及结果

本地先保留8个模型版本（旧版与7个候选），在10条已知输入上比较4个开关配置，共320个模型臂。筛选包含按对象回归单位、关闭未证实先验、置信度混合、离散度混合及经验新鲜度。全部模型可重放，失败候选也保留；这320个模型臂没有真实I/O，**不是320次服务器测速**，不能当成吞吐或p99证据。

选择进入真实测速的唯一生产改动位于`src/run_reuse.h`：只有实际发生跨轮返回才刷新共享热点经验的年龄。新对象首次访问、连续重复读取不能给旧经验重新计时；按对象年龄与经验年龄的较大值衰减，避免重复扣减。基础频率、缓存预算、真实成本、其他两模块和执行路径保持原逻辑。新增原生测试覆盖这三个因果条件。

同批候选对旧完整版，移动吞吐汇总+0.456%、p99−0.075%，但逐轮吞吐+1.380%/−0.474%、p99+0.802%/−0.949%，严格0/2。公开吞吐汇总+1.673%、p99−0.107%，严格1/2。公开第一轮新旧执行动作哈希相同，不能把该轮+1.666%吞吐归因于新的放置/搬运决策。两轮输入相同，运行波动与成本采样会影响耗时及决策；小样本不能证明因果加速或总体显著性。

修正移动复制数144→132次，只减少24MiB复制，却增加6MiB远端读取；相对NoHotspot的额外搬运仍远高于远端节省。因而这个衰减修正只缓解了一小部分预测过度问题，没有解决动态估值的净收益缺口。此次不保留候选，也不继续按输赢追加实验。

## 对论文和后续优化的含义

基础热点判断的作用与动态增强的独立贡献必须分开写。报告70支持限定输入上的整体存储收益，以及移动热点中的放置和联合准入收益；并非其他三项在所有输入都稳定提升。报告71没有补足H的稳定性能主张，也没有重新验证P/J/SIEVE，不能拼接成新版四表。

若继续开发，需验证动态估值能否更准确预测“尚未被捕获缓存满足、且会在副本有效驻留期间发生的远端读取节省”，并按观测到的预测误差校准准入，而不能只减小衰减或挑选热点输入。这个方向目前仍是待验证假设；先前若干需求折算原型已失败，不能称为已解决。现阶段写论文应明确这一限制，不把创新1包装为已确认的独立加速点。
