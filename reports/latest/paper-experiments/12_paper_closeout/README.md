# TokenFS 实验收口与论文可用结论

本次工作是对已完成 B3 实验的独立离线复核和论文主张收口，没有新增性能运行，没有更改已测算法、负载、样本量或原始结果。

## 最终决定

**可以结束本轮实验，开始撰写“热点变化下的分层缓存准入与历史自适应”的方法与实验章节。不能将原计划的“价值感知缓存管理 + GPU 亲和放置”两个宽泛创新点都写成已经验证。** GPU 亲和作为系统设计与功能能力保留，当前不列为已验证性能贡献；实测成本模型各子项也不作独立收益主张。本文中的“可写作”不等于新颖性审查通过或已达到任意投稿 venue 的要求。

建议题目方向：**面向动态热点的分层 KV 数据缓存准入与历史自适应**。这里“面向 KV”是应用目标：公开访问身份被映射为固定大小合成对象，实验没有运行真实 LLM 推理。

可写的贡献组织为：一个经实测支持的策略贡献（准入筛选与热点历史自适应），以及一个实现和实证贡献（可挂载存储原型、真实 NVMe/TCP 回放、公平对照及可复算证据）。不要把工程实现贡献包装成第二个已经证明优于现有方法的 GPU 亲和算法创新。

## 3. 核心结果：热点变化

AURA 平均完成时间 **6.788 秒**，平均吞吐 **113.25 MiB/s**。每轮完成 384 次 × 2 MiB = 768 MiB 的相同逻辑读取。

| 对照 | 对照平均耗时 s | 对照平均 MiB/s | AURA 配对吞吐提升 | AURA/对照耗时比 [95% CI] | Holm p |
|---|---:|---:|---:|---|---:|
| LRU | 7.421 | 103.64 | +9.30% | 0.9149 [0.8972, 0.9350] | 0.010254 |
| LFU | 9.143 | 84.05 | +34.72% | 0.7423 [0.7280, 0.7575] | 0.010254 |
| 近期频率准入 | 8.471 | 90.68 | +24.85% | 0.8010 [0.7859, 0.8167] | 0.010254 |

三个比较均满足预先规定的确认条件，也都达到前台耗时至少下降 5% 的点估计门槛。只有热点变化场景同时满足对三个参考的这项核心门槛。RecentLFU-admit 已有滑动近期频率与准入，是必要的较强参考，但不等同于完整 TinyLFU/W-TinyLFU/S3-FIFO。

控制变量：每组使用同一请求身份/顺序、payload、缓存配额、复制校验、后台并发、后端直接 I/O 和计时边界；应用缓存每轮重建、后端统一预热，策略顺序随机。主热点实验固定 caller=0，不把跨 GPU 访问变化混入热点变化。384 次请求分四阶段，每 96 次切换热点；每阶段约 85% 请求访问四个当前热点，其余访问背景对象；8 MiB 缓存可容纳四个 2 MiB 对象。参数在正式保留种子/窗口访问前冻结。

前台时间从请求回放开始到最后请求返回，用同机单调时钟计算；MiB/s = 总逻辑字节 / 2^20 / 前台时间。请求间元数据处理、异步决策及共享 I/O 影响都体现在该时间里；准备数据、挂载、事后校验与卸载不计入。加入后台用户态复制队列收尾后，核心优势没有反转；不把队列收尾称为全盘持久化完成。

每个场景 12 个配对完整运行。使用配对几何平均耗时比、5000 次配对 bootstrap 的 95% 区间、配对符号翻转检验及主比较家族内 Holm 校正。区间本身未作多重比较校正；显著性和效应大小一起报告，不用单个请求充当独立样本。

## 4. 机制归因：哪些消融真正支持贡献

| 关闭滑窗遗忘和热点重置 | 0.7331 [0.7204, 0.7477] | 26.69% | 0.000977 |
| 稳定热点：关闭准入 | 0.8361 [0.8217, 0.8492] | 16.39% | 0.001465 |
| 扫描：关闭准入 | 0.9191 [0.8960, 0.9418] | 8.09% | 0.001465 |
| 随机：关闭准入 | 0.9099 [0.9027, 0.9163] | 9.01% | 0.001465 |

其中 no-shift 是仅关闭快速热点重置的单项对照，12/12 配对块观察到相关机制活动和动作变化，能支持额外快速响应的速度贡献。no-aging 同时关闭自然滑窗遗忘与重置，只证明整体历史遗忘的贡献，不能继续拆出每项贡献。

no-admission 关闭整体复用/净收益筛选，支持该整体筛选在已测场景的净速度贡献；它不单独验证复制成本、服务成本等每一个项。成本项、大小项、额外价值淘汰规则，以及稳定场景异步执行，均未确认独立提速。稳定/扫描的四格交互项为正，不支持有利协同，更不能替代完整 Python RobustBenefit 模型的验证。

## 5. GPU 亲和：最终审查发现和边界

源码散列已核对为正式测试版本。`ShouldPromoteOnRead` 在 measured 模式直接进入 measured 准入，`ShouldCreateCrossGpuReplica` 在 measured 模式按已有 owner-local 副本与调用域需求作决策，绕过旧亲和状态门槛；旧副本数量门槛和 `ReconcileCrossGpuReplicas` 在该路径不执行。具体函数、行号、原文见 [源码复核](affinity-source-review.json)。系统仍有调用域计数与跨域副本能力，但这不等于原亲和算法已接入并验证。

第二轮没有独立 affinity on/off 对照。多域速度补充只是 AURA 与相同共享副本架构的 RecentLFU 比较：热点变化吞吐点估计 +14.31%，稳定场景耗时点估计 +2.22%；每条件 n=3，不能用于确认 GPU 亲和贡献。第一轮旧路径的亲和对照仅随机场景约 1.27% 耗时收益，版本、策略与路径不同，不能拼接成新版的第二个创新点。

**本次没有为凑齐两个创新点追加无效的亲和开关测速，也没有改动冻结版本再冒用旧结果。** 如果坚持原来的双算法贡献，必要工作为：

1. 将亲和放置决策实际接入当前策略，并证明开关能够改变放置；关掉亲和时仍保留相同的副本能力、总容量与可使用域，不能拿禁用整个缓存域当纯消融。
2. 给 caller-local、owner/peer-local、remote 建立可测的访问路径差异；当前共用磁盘不能支撑物理 GPU/跨机亲和结论。模拟代价只能作为模拟证据，不能冒充硬件提速。
3. 在相同热点管理下比较亲和开/关及固定放置，覆盖固定访问者、访问者迁移、共享访问和无亲和负对照；保持数据/请求/总容量/网络/复制并发一致。
4. 若主张两个策略联合，做热点自适应 × 亲和的四格对照，并单独检查交互；使用全新开发/冻结/保留集，报告实际吞吐、总时间、尾延迟和复制量，允许无收益或退化。

这是一组新的实现与实验，不是补一张现有表能完成的工作。按“现在结束实验”的收口范围，这些列入未来工作，当前不保留第二个已验证性能创新的表述。

## 6. 必须保留的负结果和适用范围

- 均匀随机相对 RemoteOnly 完成时间增加 **2.23%**，确认存在开销。上界小于 5% 的描述性容忍标准不等于零开销或等效。
- 稳定/扫描等场景相对 RecentLFU 没有确认优势；公开 Mooncake 对话对三个参考都没有确认优势；工具代理仅对 LRU 有确认优势（配对吞吐 +6.62%）。不能把公开轨迹结果表述为普遍胜出。
- 热点变化主实验每轮经验 p99 的均值：AURA **36.575 ms**、RecentLFU **34.847 ms**。这里只是描述性尾延迟，不是已证明的显著退化，也不能宣称吞吐改善同时降低了 p99。
- 变长对象 AURA 平均复制 **59.17 MiB**，RecentLFU **41.50 MiB**，没有确认速度收益，不能声称总能减少搬运。
- 容量、历史窗口、4096 请求及到达时间补充每条件仅 n=3。大容量下有负向点估计；长热点序列优势缩小。长序列同时更改基础对象/配额，不能写成只改变时长的单因素因果结论；不是小时级稳态压测。
- cn7→cn13 为真实 NVMe/TCP，但客户端缓存位于 sda 支撑的 LVM，目标是既有文件系统上的 loop backing。非独占裸 NVMe；目标缓存和其他任务争用未隔离。前台两层 O_DIRECT，后台 buffered；不声称双端完全冷缓存。
- cn7 日历时钟曾偏移约 1935 秒；耗时使用单机 CLOCK_MONOTONIC，日历偏移不参与速率计算。不能直接对齐不同主机日历日志。
- 没有真实模型 tokens/s、TTFT、物理多 GPU 扩展性、全系统鲁棒最优、强 SWAP、掉电恢复或严格物理峰值空间证据，也没有完整现代 SOTA 算法对比。

## 7. 可直接用于论文的结果段落

> 在单客户端 TokenFS 存储原型上，我们通过真实 NVMe/TCP 链路回放固定请求序列，以完整请求回放耗时及有效吞吐衡量净性能。主实验涵盖五类合成负载和两类公开访问轨迹，每场景使用 12 个配对运行。在热点变化负载中，AURA-adaptive 平均有效吞吐为 113.25 MiB/s，相对等容量 LRU、LFU 和近期频率准入参考的配对吞吐分别提高 9.30%、34.72% 和 24.85%，均通过预定的多重比较校正。单组件消融显示，相比仅关闭快速热点重置，完整策略的配对完成时间降低 20.93%，支持快速适应历史热点变化的收益。该优势具有场景依赖性：多数其他负载未确认超过近期频率参考，均匀随机相对不使用本地缓存存在 2.23% 的完成时间开销。本研究验证的是实际存储回放性能，不直接代表真实大模型推理或物理 GPU 亲和加速。
