# 第32轮：固定热点重访间隔修复

固定热点旧版退化有明确机制缺陷：把同一次突发中的连续读取算进重访间隔，导致热点价值衰减过快。第31轮旧版在16MiB热点可装入24MiB总缓存时，仍淘汰热点6、4、1、3、0、7、6。上一轮37次复制对SIEVE的30次，说明不能只归咎于规划函数算得慢。

新增默认关闭的`burst_interval_survival`：存在已观察到的重访时，以相邻突发之间的已完成间隔估计半衰期；只出现一次的突发沿用原短期衰减，所有历史仍受128请求窗口限制。到达对象和驻留对象使用同一公式，不读取未来、不判断工作负载名称、不固定热点编号，不改变暂存读取窗口。

冻结12组、6912次请求，全部完成并通过数据审计；8个比较中2/8通过现有正增益筛选。无换种子、丢弃负结果或追加大规模实验。

## 公平性、验证与限制

新版与旧版仅一个策略开关不同，同一Release程序；SIEVE保持共享暂存、磁盘O_DIRECT、SQLite FULL-WAL和1次读取准入。每组576×2MiB，24MiB总磁盘缓存、4MiB暂存上限。Full为8/8/8逻辑分区，SIEVE为24/0/0共享池，SIEVE比较是系统级比较。保留原复制提交时的容量和打开文件保护。

cn7经NVMe/TCP连接现有cn13远端存储，三逻辑消费者串行回放，没有实际GPU/CUDA/LLM。未改cn14。原生内容/复制测试与缓存目标校验通过，计时没有加入逐响应SHA。9项原生测试、101项Python测试通过；独立复核43个源码哈希、程序和固定输入身份、12组请求和墙钟、p99、最终SQLite全计数、三层字节、后台完成和资源约束。

这轮针对固定热点规划，不替代新版H/P/J消融、真实多GPU或端到端推理结果。不声称已经满足全部论文结论。速度修复结论必须与上述每对p99/排空判断一起阅读。
