# 创新1专项诊断：返回证据约束（报告72）

**18次预定实测及288次内容校验全部完成，候选未采用，原生生产实现已恢复报告70。** 移动热点汇总吞吐有所提高，但优势没有两轮重复；公开回放p99变差，均匀随机吞吐两轮下降。[完整实测表](tables.md)包含所有结果；不覆盖[报告70正式四表](../70_final_confirmation/tables.md)，不按输赢补跑。

## 本轮实际修改

首先实现了延迟预测误差校准：只对已完整经过窗口的预测结算误差，内存捕获命中不计磁盘复用，未返回对象也产生零收益标签。全局与按复用证据分组两个原型未通过模型筛选，部分公开输入错失有用复用。另检查重复后延迟搬运、成本校准后停止空位探索、已观察返回间隔支持度等方向，保留全部失败结果。

唯一进入服务器的候选新增可选的`empirical_return_support`：依据已完成的非相邻返回间隔，有多少仍支持对象当前等待年龄，对动态近期/长期估值施加折扣；一个支持伪样本避免稀疏观测直接清零，并沿用原有时间相关强度。新到达对象与驻留对象使用同一公式，不查未来或负载标签。候选各臂同时关闭`cohort_reuse_prior`，不再借历史热点经验给未观察到跨轮返回的新对象赋值。基础频率公式、空位探索、读写成本、预算、校验和持久化保持原逻辑。

这是一种有界的复用阶段持续性启发式，不是最优驻留时间预测器、置信区间或已证明的新理论。当前NoHotspot仍保留基础频率判断；本轮识别动态增强的边际收益，并不证明基础热点机制无效。

吞吐按总逻辑字节/总墙钟时间计算；p99汇总为两个运行p99的中位数，不是合并请求p99。吞吐变化为正、p99变化为负才有利。严格门槛仍要求吞吐提高、p99降低、排空吞吐不退化及机制实际改变执行动作。H仅1/6通过。

**移动平均+4.697%不能写成稳定提升。** 两轮吞吐变化分别+9.556%和−0.002921%，第二轮实际近乎持平且p99升0.524%。每轮Full与NoHotspot都做28次复制、读168MiB远端、56次规划快照和176次乐观拒绝；虽然具体执行动作序列有差别，当前计数不能把第一轮0.620秒差距解释成少读/少复制或少做规划。没有独立耗时分解，运行波动与其他执行成本不能排除。

对**同批旧完整版**，移动吞吐汇总仅+0.422%、p99−0.083%，严格1/2；公开吞吐−0.609%、p99+1.477%；均匀吞吐−0.734%、p99+1.022%。不能跨批拿报告71的旧速率比较，也不能把本轮H平均增益当作新旧版本的增益。

## 局部节省为什么仍没有成为全局收益

- 移动相对旧完整版：两轮复制145→56次，减少178MiB；规划快照299→112，但远端读取312→336MiB，增加24MiB。真实吞吐平均只增加0.422%，说明少复制与多读远端的代价需要同时计入，不能把复制减少比例当成加速比。
- 公开相对NoHotspot：少读140MiB，但多做16次复制、14次快照；吞吐两轮都有收益，p99两轮都变差。候选与旧完整版的复制/淘汰执行动作哈希在两轮均相同，不能用该对照宣称新的支持度算法改变了迁移策略。
- 均匀相对NoHotspot：少读36MiB，但多8次复制、130次快照，CPU多0.76秒，吞吐两轮下降。候选与旧完整版的复制/淘汰动作哈希在两轮也相同。新增支持度扫描会增加估值计算工作；但未启用函数级计时，不能把全部CPU或p99差异精确归因给它。

这些结果把缺口缩小为两点：新增预测在部分输入上没有产生额外有用决策；有决策差异时，节省的远端I/O也未必覆盖复制与规划成本。此次没有用删除冷读、弱化对照、挑选重复结果或更改统计口径补出正数。

## 规模、来源与验证

预先固定18次：移动74801、公开74802、均匀73702，Full/NoHotspot/OldFull各两轮，第一轮按980000+输入种子打乱，第二轮完全反序。每次1152×2MiB请求、24MiB磁盘加4MiB共享捕获。三条输入均与已检查的本地模型输入相同，属于开发数据；两轮是执行重复，不是独立样本。

Full和NoHotspot使用同一候选二进制，配置仅`measured_static_reuse_value`一个开关不同。OldFull用报告70二进制，保留旧先验、关闭新折扣；所以新旧对照同时包含这两项变化，不能分别归因。P/J/SIEVE没有重测，不能声称它们的收益在候选上已被保留。

候选二进制SHA256：`5986c837f42082fa555518c08c8ee8c0051d0c25d9728aa5f5632d31d908c357`；OldFull：`b09253aa1577e6104421b797641b8952bd151c988eb3d9bef562b82d210cde37`。协议与候选初始提交0107127，完整依赖冻结并在测速前推送d4c44d38b8154903d1c61ea251a2612f3efa41dd；[冻结版本CI通过](https://github.com/yxtmfz/tokenfs/actions/runs/36676490619)。归档286份哈希化源码、脚本、测试及所需固定数据。

最初打包漏了两份原生测试，补齐后又发现Python审计依赖和测试数据未齐。两次远端失败记录保留；最终包在本地独立通过146项Python测试，cn7通过10项原生及146项Python测试后才开始测速。所有修补都在首次测速前，算法/输入/参数未改，没有因慢而重复运行。

18次测速共20,736条请求，另288次逐请求SHA256内容校验通过。原始请求p99、墙钟吞吐、容量/缓冲上限、SQLite/JSON、动作哈希、配置和实际二进制逐项核对。审计器拒绝伪造成本样本、吞吐增益、p99和二进制凭据。恢复原生实现后两项受影响原生测试与146项Python回归通过。

本地四类筛选共480个模型臂，另40个冻结源码一致性复放，共520；包含8个候选及重复基线。模型使用固定I/O成本与即时复制，**没有FUSE、真实NVMe/TCP或真实速率/p99**，不等于520次服务器实验。延迟标签原型的前缀、成熟窗口、RAM排除和状态界限测试通过；所有模型可离线精确复放，选择进入服务器的原型与冻结原生实现动作计数一致。

实际环境为cn7三个串行逻辑消费域共享一台主机磁盘、cn13 NVMe/TCP；没有访问cn14。没有物理GPU或推理吞吐测量。前台O_DIRECT并不控制目标端页缓存和外部设备负载，短运行的小幅差异不支持总体显著性结论。

## 复现和决定

`python3.12 validation/verify-support-delivery.py .`校验清单、冻结源码、与旧版仅两份生产源码差异，重审全部请求并精确重算表格。`python3.12 validation/replay-support-models.py`重放520个模型臂及因果标签测试；均不访问服务器。原生候选源码和补丁在provenance保留，可单独重建。

**不采用此候选，不替换正式四表。** 如继续研究，应先证明新增估值改变了哪些会回本的决策，并控制估值自身的计算开销。只优化扫描速度有可能减少实现开销，但不能自动补足独立热点策略的贡献；当前尚无该项实测证据。本轮到18次固定测试结束，不扩量，也不宣布创新1已闭环。
