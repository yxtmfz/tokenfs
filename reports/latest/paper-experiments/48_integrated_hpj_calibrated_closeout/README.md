# TokenFS：严格逐项消融与三处工程修复的实测结果

**结论：完成本轮修复和小规模复核，但尚未解决三个性能缺口，不能宣布三个创新点全部成立或稳定全面优于 SIEVE。以下完整保留负结果和未触发的消融。**

前三张表均是 Full 与“完整策略仅移除一个模块”比较：H 改为静态近期频率估值（NoHotspot）；P 限制为仅请求者域放置（NoAffinity），仍保留跨域读取和共同观察；J 不扣除被淘汰对象损失与不确定性（NoJoint），仍保留复制收益判断和相同候选域。第四张才比较完整策略与等能力共享 SIEVE。不是 Full 与只启用一个创新点比较。J 的移除也可能改变实际目的域选择，因此是条件消融，不是完整因子交互证明。

最终候选同一二进制、三种固定输入、五版本，原序和完整反序共30次测速、17,280次请求。每次576×2MiB，24MiB总磁盘缓存、4MiB总捕获内存（含活跃读取/复制占用），O_DIRECT、SQLite FULL-WAL；所有版本同享执行修复与内存能力。三个串行逻辑消费者运行于cn7，已有cn13 NVMe/TCP为后端，未使用cn14。没有物理GPU或真实推理测试。

MiB/s=两次请求总字节÷两次完整前台墙钟，不能当作裸设备带宽；四张表共用同一次Full。p99为合并请求的描述值，排空吞吐包含后台完成等待。通过要求两种顺序各自吞吐>0、p99不增加、排空吞吐不下降且实际动作改变；P另需真实跨域放置，J需涉及受害者价值的准入。没有5%门槛。n=2、开发期间已知输入，不作显著性结论。

## 实际修复及其边界

1. 捕获内存采用容量受限的LRU保留，不再随磁盘复制结束或准入拒绝而消失。活跃读取、复制和已保留内存合计不超过4MiB，不能通过多复制获得额外内存预算；所有对照同样启用。
2. 本地读取也可重新填充捕获内存，消除“提升到磁盘后反而失去连续内存命中”的路径不对称。验证真实来源与只读远端锚点；本地副本删除不使有效远端内容失效，远端替换会使缓冲失效。这依赖项目只读规范对象及已校验副本的约定，不是任意并发修改文件的一致性协议。磁盘收益模型不再重复计算已由内存服务的相邻突发。
3. 初始20个物理成本样本等权，之后恢复原5% EWMA；仅在已有空闲容量内采样填充，不能为校准额外淘汰对象。此前首个59.158ms复制样本在12个后续样本后仍把估计维持约44ms，压制后续采样与缓存填充；修复了这一反馈。SIEVE本来即可填充空位，没有削弱它。

上述通用执行层加速不是H/P/J各自的创新收益。旧inflight指标现在包括复制结束后仍保留的捕获内存读取，应解释为“捕获内存”，不能继续全部称为在途复制收益。

## 尚未闭合的缺口

移动热点：原序Full与NoJoint远端读取同为138MiB、捕获内存同为910MiB，Full复制25次、NoJoint31次，但Full只有257.262MiB/s，NoJoint276.949MiB/s。少复制没有自动转化成更快；Full CPU时间2.30秒、NoJoint1.84秒，控制与执行成本需要纳入收益闭环。该计数是瓶颈线索，尚不能把全部差额归因于CPU。相对SIEVE，Full远端读取更多（138对110MiB），还存在准入响应偏保守的代价。

均匀随机：修正冷启动成本后，原序Full为103.939MiB/s、NoAffinity104.375MiB/s，亲和仍没有正收益；这里缺少稳定消费者分工，本来就不能预设每种亲和必胜。必须保留为边界和回归检查。

尾延迟与稳定性：多项p99仍退步，部分增益随运行顺序变化。短负载与共享存储噪声不能通过挑选赢家或汇总掩盖；后续应做已冻结的独立输入检验，不能反复使用相同开发种子直到所有数值变正。

实验辨识：当前固定热点工作集容纳于总缓存，H/J在两轮可能完全不改变决策。此场景可做不退化检查，不能证明H/J贡献。最小必要补充是预先冻结一个确实产生容量竞争/热点切换的负载，验证H/J动作改变；必须与现有全部回归场景一同报告，不能替换负结果。物理GPU亲和主张仍需真实GPU共享KV实验，否则论文应限定为逻辑消费者缓存域。
