# 第26轮：剩余复制成本的单变量验证，未获得新增提速

本轮固定12组开发试验：两个热点种子3251/3252、一个均匀随机种子3253，各运行IncrementalHP、AdaptiveHP、PoolSIEVE1、PoolSIEVE2。全部保留，没有选种子重跑、没有大规模实验。实验均已结束。

**结论：新成本选项修正了决策口径，但三个负载的复制次数和远端读取字节均未变化，没有测得新增吞吐收益。因此不把它升级为默认策略，incremental_copy_cost仍为false。稳定跑赢SIEVE-1hit的目标尚未达到。**

冻结门槛：热点对每个SIEVE都需配对≥5%、两次都更快、每次p99不退化；随机要求速度和p99不退化。总体未通过，不能把其中有利单项拼成“全部通过”。小样本不能判断不足1%的差异是否稳定。

旧控制器对SIEVE的同批次补充比较（次要分析，不冒充新选项收益）：热点对1hit +1.45%（一胜一负）、对2hit +8.31%（两胜），第二热点种子的p99分别高1.16%和1.22%；随机对1hit +25.79%、对2hit +23.03%，p99分别低16.80%和13.03%。随机仅一个种子，尚未确认可重复性。不要与报告25不同种子的均值拼接成修复收益。

## 根因检验：这次修正为什么没有提速

旧样本把复制流水线时间与前台捕获时间相加，其中准入规划在决定是否继续时也已经发生。新模式分开记录它们，收费项为流水线耗时减去已完成规划。仍完整计算淘汰执行、写入、校验、fsync配置和READY发布；没有按主观权重降低代价，也没有把异步复制假设为免费。完整系统耗时和所有指标仍保留。

|种子|策略|复制次数|远端读取 MiB|执行前copy_cost拒绝|平均完整样本 ms|已发生规划 ms|已发生捕获 ms|实际收费 ms|
|---|---|---:|---:|---:|---:|---:|---:|---:|
|3251|AdaptiveHP|55|220|0|18.562|1.459|0.524|18.562|
|3251|IncrementalHP|55|220|0|18.441|1.470|0.530|16.440|
|3252|AdaptiveHP|39|156|0|18.834|1.426|0.529|18.834|
|3252|IncrementalHP|39|156|0|19.261|1.542|0.556|17.164|
|3253|AdaptiveHP|20|550|0|24.909|1.983|0.836|24.909|
|3253|IncrementalHP|20|550|0|25.508|1.886|0.868|22.754|

本轮新旧控制器在三个输入上分别都是55/39/20次复制、220/156/550MiB远端读取，且执行前copy_cost拒绝均为0。收费虽变小，但没有观察到这些计数改变，实测新/旧吞吐为热点−0.07%、随机−1.21%。不能据此声称解决了上轮3241种子的25次拒绝：本轮新种子并未重现该失败条件。

随机负载中，SIEVE-1hit/2hit分别复制285/258次，远端读取606/596MiB；原控制器复制20次、远端550MiB。少搬运与真实提速同时出现，说明成本准入在这次无明显连续热点的输入上有实际价值。它不是亲和模块的独立因果证明，也不是新成本选项的贡献。

## 已完成与未解决

- 已完成：显式区分已发生/剩余成本；原控制器与候选版本的单变量对照；保留两种强基线；补充一个随机负载；全量可复算证据和失败门槛。
- 未解决：热点对SIEVE-1hit的稳定优势、p99完全不退化、上轮3241拒绝失败的稳定复现与修复、当前版本热点/亲和/联合各自的独立贡献。
- 下一步有证据支持的方向：对原失败条件检查复制就绪与下一次访问的时间关系，区分成本偏高、排队和复用窗口过短；优先建立可控时序复现。此次没有实现就绪时间模型，不能称已解决联合控制器问题。
- 不通过更换输入、放松基线或把候选选项打开来宣布胜利。本轮不会追加大规模运行。

## 控制变量与限制

cn7客户端通过既有cn13 NVMe/TCP挂载读取远端；3个串行逻辑消费者，没有物理GPU、CUDA或LLM端到端实验。每组576×2MiB请求、24MiB保留缓存，4MiB暂存上限。完整版8/8/8MiB分区，对照共享池24/0/0MiB，系统对比容量相同但几何不同；新旧控制器的分区完全相同。SIEVE也启用相同读填充与请求级成本计数。两层前台O_DIRECT、内容校验、SQLite FULL-WAL保持原配置。细粒度请求探针和控制路径探针关闭，summary中的open_ms/layout_wait_ms占位0不得解释为零耗时。

顺序在冻结协议中预先确定：3250种子打乱，第二热点反序，随机轮转。12组每格一次；反序并不能消除所有时间漂移或缓存状态影响，需后续独立确认。只校验全部缓存目标内容，性能轮未对每个用户响应计算SHA；实际读路径内容/部分读取/源变化等由原生测试覆盖。
