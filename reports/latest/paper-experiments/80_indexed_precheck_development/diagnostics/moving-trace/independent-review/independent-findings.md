# Source 80 moving Full/NoHotspot 独立诊断结论

这是冻结 source 80 的两臂逐请求诊断，不是新增正式性能实验，不能并入四张正式结果表。没有修改 source、配置、输入或任何原始结果，也没有删请求、换种子、重选轮次。

## 身份及复核

- 原始包 SHA-256：`c71dec53662c741e0423814c8a8ff050a34ce97094f81dcd448d7a789e2e7fb1`。
- 二进制 SHA-256：`f5e2981b8b4f0ce54bb2994e53998608de4cec4a3c861531e8e86e0aab031f71`。
- 2 × 1152 个请求，各 9408 个 trace events，dropped=0；27 个 raw 文件无 SQLite sidecar。首次记录的全部 27 个 SHA 在分析完成后逐一复核相同。
- 独立 audit PASS；release fence、后台计数、CPU 配置、实际索引启用及两条索引定义均已通过冻结工具核验。
- 现有 7 个 parser 输出保留冻结；额外的 `decomposition.py` 只读它们和 raw，生成 `decomposition.json`。另一位归档审查者已确认独立与 root 的 7 个 parser 输出逐字节一致。

## 能确认的机制事实

同一个请求序号的 key、caller、首次/重复分类和 backend tier 在两臂全部一致：67 次首次远端、17 次重复远端、148 次重复本地、920 次 RAM。两臂均为 28 次复制、58,720,256 复制字节；696 次物理 pread、486,539,264 物理读取字节；5760 个 FUSE read callbacks。

这是当前输入上 **H 没有带来读取层级或净 I/O 数量优势的直接证据**。它不是“H 对所有容量和所有负载都无效”的证明。44 个本地请求的具体 domain 落点不同，因此也不能把它写成“所有决策完全相同”。域是当前逻辑 GPU 模拟域，本结果不是多物理 GPU 的测量。

## 同序号分解

Full 和 NoHotspot 的诊断墙时分别为 6.758833755 / 6.696129209 秒，差 62.704546 毫秒。全部请求响应之和差 63.167786 毫秒，外层控制循环剩余差 −0.463240 毫秒。以下分解是描述性的实际时间恒等式，不是对策略的因果分摊：

|响应组成，Full−NoHotspot|总差（ms）|
|---|---:|
|客户端 open|−29.443948|
|客户端 read|+91.188190|
|客户端 close|+0.093777|
|其余 IPC/调度区间|+1.329767|

客户端 read 总差进一步分为 pread 区间 +44.445192 ms、read callback 内非 pread 区间 +32.880759 ms、客户端 read 与 callback 之差 +13.862239 ms。重叠的后台、getattr、release、规划区间不可再与这些时间相加。

index 844（从 0 开始，key 17，首次远端）特别明显：

|指标|Full|NoHotspot|
|---|---:|---:|
|响应（ms）|71.248458|23.847563|
|pread 区间总和（ms）|67.382246|19.781461|
|copy pipeline / shared plan 重叠（ms）|0 / 0|0 / 0|

这个匹配请求响应差 47.400895 ms，约为全墙时差的 75.6%。Full 两个有数据返回的 callback 内 pread 区间分别为 48.526142 / 18.852678 ms；NoHotspot 为 9.898404 / 9.879885 ms。还各有一次约 3 微秒的 EOF pread。**pread 的计时可以包含被抢占和后端等待；现有 trace 不能把它进一步确认为 NVMe、网络、设备或 CPU 调度问题。** 每请求物理 I/O 次数、字节、偏移并未被仪器记录，仍为 null，不能根据 callback 数量代填。

所有结果均保留 index 844。这不是删除异常后重算优势的理由，也不能由单对诊断推断其出现概率。

## p99 的证据边界

两臂各自最慢的 12 个请求全部为首次远端读取。Full p99 是 index 776，26.965899 ms；NoHotspot p99 是 index 416，26.816452 ms。同一 index 776 在 NoHotspot 为 26.962800 ms，仅差 0.003099 ms。最慢 index 844 不等于 p99 排名位置，不能拿它解释整个 p99 差异。

两臂 top12 的 copy_pipeline 重叠均为零。不过不能写成“完全无规划或复制活动”：Full top12 有累计 0.753894 ms 的 shared_plan 重叠，NoHotspot 为 0.836343 ms；Full index 0 另有 0.113283 ms 的 copy_attempt 重叠。另有前一个请求的 release 重叠。这些是重叠区间，不是已证明的阻塞开销。

对于首次出现、没有可用过去对象内容的 key，修改 H 的复用估值不能凭空消除这次按需远端读。当前 H 的合理作用应体现在之后的重复访问及复制/淘汰选择；本诊断的这些路由收益与 NoHotspot 相同。不能靠调预测数值承诺当前输入的冷读 p99 同时变好。

## 是否还有值得立即修的代码缺陷

本次 trace **没有发现新的、已定位到代码且足以解释失败的正确性缺陷，也没有发现 H 独立 I/O 收益被某个已确认实现缺陷掩盖的证据**。

- Full 尝试 60 次 domain 规划、NoHotspot 38 次，但 shared_plan 事件总时长仅差 1.492024 ms，且有重叠；不能据此解释 62.7 ms 的全部墙时差。已持久化的 `copy_cost_planning_us` 反而 Full 更低。不能把约 30 ms 的 CPU 差武断归于几次 pow 或 H 计算。
- 两臂预筛累计耗时仅差 334 微秒。索引局部优化减少扫描已通过正确性和原生微基准，然而该事实并不自动证明端到端加速；应保留正式索引对照未改善的结果。
- read callback、前台元数据路径和完成 fence 仍有共同成本。现有 trace 缺少 SQL/fsync 的独立 span，无法区分 CPU、锁、SQLite 和调度。没有证据支持再次修改某个共同路径就能给 H 产生独立性能收益。

若将来继续工程优化，应先有可复现的共用路径成本或明确缺陷，再做保持语义的修复；这是共同实现优化，不能冒充热点创新的消融收益。本诊断本身不支持立即启动新的 24 组候选实验。

## 本轮收口建议

1. 保留正式 80 全部正负结果，诊断只作附录。当前固定 24 MiB / 4 MiB RAM 的 moving 输入不能作为 H 稳定独立加速的证据；也不能由一次诊断宣布其真实效应严格为零。
2. 不继续按这个输入的正负号微调估值或反复测速等待四表全正。此前对象先验、运行单位、驻留期、RAM 价值等候选已有混合或负面结果，此 trace 没有给这些方向新增可辨识的根因。
3. 收紧论文中热点独立收益、GPU 物理亲和和联合控制器普遍优势的主张。当前有证据支持的是给定逻辑域环境及已报告输入范围内的实际结果，所有回退应公开。
4. 若论文必须宣称 H 的独立普遍收益，仍缺预先定义、具有 H 可影响复用/淘汰空间的代表性负载及独立验证。这是待补证据，不能改容量/挑种子后替换现有负例；新的场景应补充而非覆盖当前输入。

科学上不能承诺有限修改或重复测试会让全部 16 个比较严格为正。当前证据足以给出清楚的“已达到/尚未证明”边界，不足以把仍未达到的目标写成完成。
