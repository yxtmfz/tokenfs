# 三个创新点与整体性能的统一小规模验证

固定热点3271、移动热点3293、均匀随机3273，五版本共15次、8640次请求。所有版本关闭探针，均使用相同的后台指标批处理和4MiB共享保留缓冲；此预算包含活跃读取与复制所占的内存，不能超额。前三张是完整策略分别关闭一个模块的消融，第四张才是外部整体比较。四组比较共用每条输入的同一次Full；不能分别挑选不同Full获胜运行拼表。

H：仅最终时变热度估值对比静态近期频率估值，保持执行与缓存能力；旧开关在causal_window中仍控制Survival衰减，但不执行显式域重置且不控制新增重访摘要和突发预测，不足以完整消融当前时变估值。P：跨逻辑域放置对仅请求者放置；J：联合扣除受害者损失/不确定性对独立复制收益准入；整体：共享SIEVE1。同能力24MiB磁盘、4MiB在途缓冲，未削弱对照。P不能推导物理GPU通信或推理性能；四组为条件增量，不能当作完整2×2交互证明。

## 复核和边界

来源、程序、配置哈希在manifest/freeze中；独立复核核对全部请求字节、SQLite计数与顺序、三层服务成本、复制及队列完成、错误、24MiB磁盘和4MiB缓冲上限，从原始墙钟重算所有速率和p99。源码、原始数据和审计脚本均归档。测速不逐请求哈希，保留副本在计时外校验；未做真实GPU或LLM端到端实验。cn7通过已有cn13 NVMe/TCP，未用cn14。每次576×2MiB、3串行逻辑消费者，同步FULL-WAL不变；服务端缓存及其他用户IO未全局隔离。

复算：将原始归档解压为integrated-hpj-calibrated-data、源码为integrated-hpj-calibrated-source，validation/review-calibrated-hpj.py放在两者同级，用Python3.12运行并传参数integrated-hpj-calibrated。[草稿PR20](https://github.com/yxtmfz/tokenfs/pull/20)，未合并。所有负结果保留，不等同于三个创新点全面通过。

本轮全部版本均可保留本地及远端读取的捕获内存；4MiB是活跃和保留内存总预算。前20个成本样本等权，之后5%平滑；仅已有空位允许成本校准填充，不额外淘汰。源提交CI36520361145成功。
