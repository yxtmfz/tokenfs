### 移动热点：新对象先验产生大量未服务磁盘读取的副本

Full多复制45次（90MiB），只少了6次远端读取（12MiB）；RAM读取均为920次。42次已结束的零磁盘命中驻留全部有RAM命中。其中38次以net_gain通过正常准入、4次属于空位校准探索；40次记录了正的cohort先验，41次在淘汰后直到该输入结束也未再访问，仅1次后来返回。

这不是仅凭命中率推测：这些副本在驻留期没有服务local读取，期间相同对象请求由已有RAM捕获服务。先验和零收益同时出现不证明每一项决策都只由先验决定，但为后续单变量检验明确了对象集合。**优先针对“未观察到跨轮返回的新对象借用总体复用经验”与RAM/磁盘收益重叠，而不是继续整体提高热点权重。**

已知反例必须保留：报告72取消cohort先验并加入返回支持度，虽显著少复制，却没有稳定提速。不能因为本次40次带先验的零收益驻留，就宣布“一律关闭先验”已经是正确修复。

### 公开回放：对象确实返回，但部分副本活不到返回时刻

Full的16次已结束零磁盘命中驻留在区间内也没有RAM命中；其中10次淘汰后又从远端读取，另6次直到输入结束未再访问。10次后续返回来自对象0–4各两次驻留：第一次空位校准副本，第二次正常net_gain准入副本。首次淘汰到下次远端读取约368–564ms；再次淘汰到下次远端读取约1719–1848ms。**估到“将来会重用”，并不等于当前容量与淘汰顺序下该副本能活到那时。**

NoHotspot的6次已结束零命中驻留均为空位校准对象，淘汰后该输入没有再返回。另一方面，Full总磁盘读取仍比NoHotspot多15次、远端少30MiB；不能将整个动态热点模块判为无效，也不能只删除这些复制而假设其他命中保持不变。

## 排除和仍不能归因的部分

- 复制锁等待总计不足0.05ms/运行，当前这四次的排队锁不是大头。
- 移动Full/NoHotspot全规划跨度总计97.751/47.995ms，复制尝试跨度484.855/176.418ms；公开对应372.533/361.925ms、225.953/151.441ms。跨度有重叠，不能相加当作墙钟损失或精确反事实成本。
- 公共回放Full有38次复制尝试、33次成功，区别已被保留；原成本样本只描述成功复制，不能代表所有拒绝工作。
- 排序估值缓存已经存在；“只收剩余复制成本”在报告26也试过，没有新增提速。它们不能再次作为未经试验的新方向。
- 4次是有诊断开销的已见输入，每臂每场景仅一次。原始速率/p99保留在result.json并已复算，但不拿来替换正式四表，不声称稳定加速、统计显著或创新1已经闭环。

## 下一次策略修改应针对什么

1. **先做RAM覆盖感知的磁盘准入候选**：把捕获期的连续重复和RAM释放后的磁盘机会分开；只借用有实际跨轮返回证据的群体经验，并对已结束驻留的实际磁盘服务结果校准先验。不能把尚未淘汰或观测结束的对象当零收益训练。目标是削减移动场景中这38次正常准入却无磁盘命中的副本，同时保住真实返回对象。
2. **再做返回时刻与可驻留期的一致性候选**：公开输入的缺口是过早淘汰，因此到期判断应基于已观察返回间隔和当前容量竞争；对到达与驻留对象用同一估值口径，保留联合决策的受害者成本。不能用负载名、未来轨迹或已知固定热点名单。
3. 若尝试延迟到RAM退出再搬运，必须保持4MiB总预算，不能额外保留待写缓冲；也不能把等待写完塞进前台Open而忽视p99。这是可检验的工程方向，**尚未实现或证实提速**。
4. 候选先在已知输入做机制检查，再冻结少量真实Full/NoHotspot/旧Full对照。必须同时检查少复制是否换来更多远端读取，以及吞吐、p99和其他消融是否退化；未通过就不升级生产策略。不以结果好看为理由反复补跑。

本轮不再另写一个凭阈值猜测的热点公式。已提交的修复是可关闭的诊断：实际源选择位置和时间、单调READY/EVICT/ADMIT事件、包括早退的规划范围，以及包含等待的复制尝试范围。公式、缓存预算、淘汰保护、内容校验与读写成本均未改变。
