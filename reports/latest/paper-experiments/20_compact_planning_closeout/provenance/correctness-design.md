# Compact planning and read accounting: correctness boundary

The changes optimize the experimental measured engine; they do not change its reuse estimator or relax synchronous metadata durability. Both new flags default to false.

`compact_measured_planning` requires immutable canonical data, measured policy and the causal request window. A single SQL statement reads committed canonical residents and READY replicas plus each destination's exact access order. The physical-file and configured-location checks exclude unavailable copies before computing shared coverage. Open logical objects are excluded from victim candidates. Replica bytes come from the replica row, not an unrelated canonical physical path.

A snapshot used for speculative admission or destination selection is never a commit authorization. `EnsureLocalCapacity` obtains the layout lock, checks physical directory usage, re-evaluates current values and protected objects, then fetches only the full metadata for the victims selected by that recheck. It uses their original order and combined loss, preserving multi-object admission. Missing/non-READY selected replica metadata aborts. It still checks physical sizes, open handles, existence and quota before completing eviction/copy. Unexpected unmanaged bytes remain counted by `DirectoryBytes`; a snapshot cannot hide them. The single copy worker/copy mutex and existing final checks remain in force. No cache of old plans survives across operations.

`lean_read_accounting` is permitted only for immutable readers using measured or read-through policy, with legacy affinity placement and prefetch disabled. These paths do not consume the old wall-clock affinity classifier. The optimization omits that classifier's event table updates, but retains object read counts, per-GPU read counts, access order and share count. The selected replica's timestamp update joins the SAME `BEGIN IMMEDIATE`/`COMMIT` transaction as the logical read; the database still uses `journal_mode=WAL` and `synchronous=FULL`. A failed transaction rolls back both. No test arm lowers durability or disables byte/checksum verification.

All six speed arms receive lean accounting. All five measured arms receive compact planning. This prevents assigning a common accounting speedup to a proposed H/P/J innovation. PoolSIEVE2 uses its native simpler eviction path under the same accounting and durability rules.

Regression coverage includes original and compact placement, duplicate shared coverage, valid-state equivalence of incoming/victim values and selected victims, multiple-victim eviction, pinned-object rejection, preserved remote canonical data, stale and unconfigured copies, persisted batched counts and timestamps, and invalid configuration rejection. Offline evidence auditing additionally compares every persisted GPU/object count with the input trace and confirms that only the unused legacy event table is absent.

The compact query visits the current resident set. Large-cache scaling and multiple physical GPU/NUMA links are not established by this small fixed-capacity test. This implementation retains location-independent measured I/O rates; it is not a heterogeneous-link optimizer.
