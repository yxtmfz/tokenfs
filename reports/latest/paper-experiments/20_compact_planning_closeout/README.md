# 最后小规模实测：热点、亲和、联合及整体速度

本轮固定完成18次测速和6组逐请求内容验证，保留全部结果，没有追加种子或更换统计口径。

**热点单独 +8.35%，亲和单独 +14.65%，联合控制 +5.88%；完整版本相对基础共享 +19.68%，相对同总容量共享SIEVE -1.96%。**

每次实际读取1152MiB；吞吐为读取字节除以完整单调时钟前台耗时，包含请求分发、FUSE、元数据、实际I/O和控制开销。不是命中率、模拟代价或预测速度。表中MiB/s为三个种子的算术均值，百分比为同种子配对几何耗时比。

|---|---:|---:|---:|---:|
| H / Shared | 93.60 | 101.42 | +8.35% | 3/3 |
| HP / P | 107.34 | 112.04 | +4.39% | 3/3 |

H关闭只去掉剩余复用衰减，保留相同观测窗口、P/J配置和工程优化。第二行验证加入亲和后，热点机制是否仍贡献真实速度。

## 数据支持的结论和仍未闭合的部分

**联合控制已通过本轮5%先导筛选，但全部性能目标仍未闭合。** HP相对Independent远端读取从388降至326MiB（−15.98%），复制从158降至97.33MiB（−38.40%），CPU从4.267降至3.877秒（−9.14%），完整前台减少0.604秒；不是仅把复制量降下来却增加了前台远端读取。

HP相对共享SIEVE只少读远端2MiB、少复制2.67MiB，CPU多0.147秒，前台仍慢0.198秒；三个种子分别慢1.66%、0.52%、3.67%。当前策略在本场景的I/O节约很小，尚未抵消控制与共享访问路径的开销。CPU和I/O重叠，不能把这些差值当作严格因果耗时分解，也不能靠扩大同类样本解决系统性的均值差距。

HP平均p99为36.42ms，PoolSIEVE2为35.46ms、Independent为35.87ms。逐种子记录见`development/tail-pairs.json`。完整策略中的热点增益为4.39%，虽然3/3同向，但未达5%门槛。四格交互项均值为+0.497秒，本轮不能支持超加性协同；J相对Independent的新增收益与超加性是不同命题。

因此可写成“在本合成负载和分区约束下，热点、亲和、联合计价分别出现受控的先导收益”，不能写成“完整版本全面超过强共享缓存、尾延迟更低或三个创新已正式证实”。这仍是逻辑域存储实测，不是物理多GPU推理验证。若按当前结果开始写作，应保留上述边界；本轮结束不等于论文证据全部闭环。

## 本次具体修复

- 把反复逐副本查询改为单次驻留快照，保留真实文件存在性、已打开对象和共享覆盖检查。
- 容量重检仍在执行前进行，但直接使用该次重检选出的完整受害对象集合，避免再扫描、再排序。未知文件和临时文件仍计入物理容量，不绕过配额。
- 将逻辑访问计数与被读取副本的时间戳合并在同一个SQLite事务中。`WAL`及`synchronous=FULL`不变，没有通过降低持久性换取性能。
- 对全部六种策略一致跳过不被当前策略消费的旧亲和分类事件统计；逐域/对象计数、共享计数、访问顺序、时间戳及策略事件保留。全部五种measured组一致使用精简规划。公共工程优化不归功于某个H/P/J创新。
- H/P/J的复用公式、参数、真实成本采样、复制校验路径均保持上一轮版本，没有看本轮结果后调参。

新选项默认关闭，启用时检查其适用范围。代码正确性说明见`provenance/correctness-design.md`。

## 完整性、控制变量与限制

- 77项Python测试与3项C++测试通过，包括新旧规划一致性、多对象淘汰、pin保护、共享冗余、过期/未配置位置、合并事务计账和配置保护。
- 6种策略、3个新种子3001–3003；每个种子相同输入、O_DIRECT、异步复制与校验，先冻结源码/二进制/配置再运行。每种策略在三个种子中各处于一次早、中、晚执行位置。
- 原始请求、实际策略动作、每域容量、local/remote/peer字节守恒、后台收尾与校验结果都进入审计；独立复算全部汇总、配对提升和交互项，并直接从SQLite核对逐消费者及逐对象读计数。
- 本轮只有三阶段热点与消费者变化的一类合成场景。前两轮负结果保留，不混合版本和种子计算本轮速度，也不把跨轮均值差当成代码优化的因果幅度。
- cn7客户端的3个逻辑域位于同一主机磁盘，已有cn13 NVMe/TCP为远端；cn14未使用。没有CUDA、NVLink或物理多GPU推理。共享目标端页缓存未受控清空。
- 创新性不等同于有三个开关。本轮只是降低已有候选策略的工程开销；没有新增“第一次共享缓存/指数衰减/联合成本”之类未经证实的主张。候选创新及相关工作边界见`provenance/novelty-boundary.md`。
