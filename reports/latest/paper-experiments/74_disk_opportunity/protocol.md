# Disk opportunity candidate: four-table development

Report73 found RAM-only copies in moving bursts and recurring public objects evicted before their next return. This candidate changes only H's optional demand forecast. It does not promise all-metric improvement.

`disk_opportunity_value`, default false, requires persistent causal shared run reuse and retained captures. It has no effect on `measured_static_reuse_value=true`. A run is a maximal adjacent same-object sequence. For an object with n completed observed return intervals, mean interval g=max(4,mean), age a since its current run started, and existing observation window W, forecast disk opportunities as W/g * n/(n+1) * 2^(-max(0,a-g)/g). Adjacent requests cannot multiply this estimate; no estimate exists before a distinct return. A completed gap is observed at the start of the next run, with no future trace access. After the expected return time it decays; the existing bounded run-history budget and observation-based competition discount remain.

The final disk-demand value is max(existing recent value * existing RAM/run scale, forecast * existing competition factor). The two overlapping estimates are not added. Incoming and resident copies use the same function. The candidate suppresses transferred first-run cohort demand. Existing calibrated free-headroom exploration, cost samples, uncertainty margin, placement, joint victim-loss charging, capacity/pin rechecks and data validation are preserved. The recent estimate is still globally scaled; this is not a complete tier-specific demand estimator or a proven residency optimizer.

Model selection considered ten known inputs (four moving, four public, one stationary, one uniform). Retain every candidate and result. Deadline-only/residual-only estimates regressed several inputs. Delayed RAM-retirement admission was modeled optimistically but not implemented because its real buffer-pressure and tail costs are unresolved. Selected recent-floor candidate reduces copies without extra remote reads relative to NoHotspot on the four moving model inputs, and improves uniform model counts; public73602 still regresses. These are fixed-cost model counts, not measured speed or p99, and not independent confirmation.

## Frozen real experiment

24 runs: moving74801 and public74802, each Full/NoHotspot/NoAffinity/NoJoint/PoolSIEVE1/OldFull, two opposite-order repeats. First order uses Random(990000+seed).shuffle, second reverses it. Each1152×2MiB requests, identical24MiB disk+4MiB capture budgets, complete cold requests, foreground O_DIRECT, all tracing disabled. cn7 has three serialized logical consumer domains on one host disk, cn13 supplies the existing NVMe/TCP mount; no cn14 or real GPUs.

Full,NoHotspot,NoAffinity,NoJoint share the candidate binary and differ by exactly the corresponding H/P/J switch. SIEVE shares the same implementation capabilities but uses one pooled24MiB geometry; it is a system comparison, not a single-switch causal ablation or an optimized standalone SIEVE. OldFull is the frozen report70 binary b09253aa1577e6104421b797641b8952bd151c988eb3d9bef562b82d210cde37. Source, build, configs and input hashes freeze before timing. A separate96-request per-arm content sweep (576 checks) is excluded from performance statistics.

Primary outcome actual logical bytes/full monotonic wall time; p99 is nearest-rank request response latency including dispatch, open, reads and close. Preserve drained time, tier traffic, copy counts, CPU, decision action hashes and all failed comparisons. Four tables compare Full against NoHotspot,NoAffinity,NoJoint,PoolSIEVE1. Report each round and pooled throughput (sum bytes/sum time) plus median of per-run p99; a median is not a pooled request quantile. A win requires throughput>baseline and p99<baseline, with strict secondary checks for non-regressing drain throughput and actual mechanism activation. No fixed5% threshold. No result-conditioned extra seeds/repetitions, no mixing historical P/J results into these tables. This fixed matrix ends with all results disclosed, including failures; small repeated known inputs cannot establish statistical significance.
