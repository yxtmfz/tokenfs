# Persistent run recurrence: bounded development repair

The previous balanced 18-run batch showed 30 of 36 hot evictions following scan admissions. The request window forgets earlier bursts and makes sustained residents appear worthless. This repair adds a bounded summary of completed run lengths and observed start-to-start return intervals; no key labels, future requests, cache capacity or workload identifier enter estimation. A single burst has no sustained estimate. The value is the maximum of the old estimate, remaining burst estimate and confidence-shrunk sustained forecast; the latter decays after mean interval plus one observed standard deviation of grace. Grace is a heuristic, not a statistical confidence limit. Incoming and resident values share the formula. The feature is opt-in and defaults off.

Freeze one binary and 18 speed runs: stationary seeds 3271 and 3291 twice each, moving 3293 and uniform 3273 once each; three arms Full (new flag on), WindowFull (previous two fixes), PoolSIEVE1. All six arm permutations occur once across blocks. No new sweeps or adaptive stopping. The two stationary runs per seed are exploratory repeats, not sufficient for publication significance. The known stationary seeds are development data, not held-out confirmation.

Each run has 576 serialized reads of 2 MiB, equal 24 MiB disk quota and 4 MiB in-flight capture limit. Three logical consumers, no physical GPU measurement. NVMe/TCP on cn7 to existing cn13 storage; backend direct I/O, SQLite FULL-WAL and all other features unchanged. Timing is actual end-to-end bytes/wall time; additionally report background-drained throughput, request p99, copies, remote traffic, hot evictions, CPU and RAM. Do not equate fewer hot evictions with faster runtime. Retain every result. No 5% threshold: per-pair screening requires positive speed, nonregressing p99 and drained speed; same-source WindowFull attribution also requires changed executed actions. No claims of universal superiority or whole-paper closure.

Correctness includes native regression tests for recurrence surviving request-window expiry, one-off scan exclusion, censored active run, decay/moving recovery, bounded metadata, symmetric estimation, and capacity/pin regressions in the existing suite. Speed runs validate byte accounting, durable SQLite metrics, capacity, completion and zero errors; they do not hash every returned request, so this is not a fresh end-to-end data-integrity certification. Freeze sources, binary and spec before running; independently recompute summaries and audit original logs.
