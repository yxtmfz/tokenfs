# 与共享 SIEVE 的小规模对照：实际结果与剩余缺口

已完成固定18次真实测速、7组逐请求SHA256校验；80项Python测试、3项C++测试全部通过。原始记录完整、独立复算通过；未追加种子、替换失败数据或在看见本轮结果后调参。

**热点变化场景：新版相对共享SIEVE-2hit +5.12%（3/3更快），相对旧完整版 +5.44%（3/3更快）；相对共享SIEVE-1hit −0.28%（1/3更快）。随机访问场景相对两种SIEVE仍退化约4.8%。** 原共享SIEVE-2hit的速度差距在本轮先导中得到解决，尚未证明全面优于SIEVE，不能称为完美结果或直接宣布论文性能主张全部闭合。

## 原因、改动与机制证据

1. 旧版只依赖对象自己的历史复用。旧报告20中，一次短暂连续访问的对象分别被复制18/24/23次，和SIEVE-2hit相同；远端读取量几乎相同，控制开销没有换来足够收益。
2. 新版从最近已结束的连续访问段学习“当前还可能剩下几次访问”，至少8个完整段才启用预测；当前尚未结束的段不参与训练。运行时不读取种子、阶段标签、未来请求或固定的四次访问常数。
3. 新估值取“旧长期估值”与“短期剩余复用估值”的较大者，避免双重累计；准入仍扣除真实复制成本及被淘汰数据损失。进入缓存前再次检查当前收益、配额和被打开对象保护，复制校验保持不变。新开关默认关闭。
4. 三轮执行并提交的首次读取预测准入为41/36/47次。远端读取从旧版336降至256MiB（−23.81%），复制量同为96MiB；这条证据解释了同期+5.44%的实际速度提升，不能只拿预测分数代替速度。
5. SIEVE-1hit本来就第一次访问时缓存，在本场景达到117.32MiB/s，新版116.98MiB/s尚未超越。它每轮远端读取247.33MiB，也少于新版256MiB。新版相对SIEVE-2hit的优势主要解决了准入时机；本轮没有证明额外的普遍SIEVE优势。

## 保持的实验条件

同一Release二进制、同块内相同输入和顺序、每组空应用缓存、真实cn7→cn13既有NVMe/TCP、前台两层O_DIRECT、相同异步复制及内容校验、相同SQLite FULL-WAL持久化计账。总容量均24MiB：完整版3×8MiB；共享SIEVE为24/0/0。池化参考仍保留更自由的容量组织，不把它假装成单字段消融。三个逻辑访问者串行发请求，数据位于同一客户端磁盘，不是物理多GPU推理测试；目标端页缓存未受控清空。cn14未使用。

## 已完成与仍未完成

- 已完成：复用预测代码、真实存储运行、两种SIEVE基线、小规模随机边界、内容/计账/配额/背景收尾校验、源码及二进制冻结和全部结果复算；新旧策略单开关对照。
- 已达标：本轮热点变化场景相对原SIEVE-2hit的≥5%先导速度门槛。
- 未达标：相对SIEVE-1hit稳定提速、随机访问无明显退化、尾延迟改善、独立留出确认以及新版本H/P/J各自的消融重验证。本轮不能沿用报告20的百分比为新版本三个组件背书。
- 后续有价值的方向：按观测复用强弱校准长期受害对象损失及规划触发频率，避免随机访问下“少复制却多读远端”；与同配额SIEVE比较，分离布局成本。任何新修改都必须重新冻结并对照两种SIEVE，不能只选择较弱准入规则。
- 保持固定小规模预算，本轮未扩大到数百次，也未通过选择新种子把未通过项变成通过。

`raw/cn7-evidence.tar.gz`包含全部原始请求、结果、配置、数据库和策略事件；`provenance/source.tar.gz`为实际编译源码；`provenance/freeze.json`固定源码、二进制和输入；`validation/independent-review.json`为离线复核。额外修改副本中的字节数、配额、时间线和持久化读计数均被审计拒绝。离线审计脚本单独保存在provenance中；它不参与运行时策略。
