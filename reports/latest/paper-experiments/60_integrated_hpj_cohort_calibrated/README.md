## 本次修复及因果解释

新对象先验此前按短突发内的访问间隔衰减，容易在下一次跨突发重用前过早降低新热点的价值；同时，新颖度折扣又对已经按年龄衰减的直接近期证据重复打折。最终版本使用已观察到的跨突发返回间隔估计新对象寿命，以已经衰减的近期证据作为价值下界，只对持久预测项应用竞争折扣。新对象先验有上限、历史队列有界，对象出现自身重复证据后停止借用先验。来件与受害者使用同一估值规则，不读取未来请求或输入标签。

共享元数据路径另外复用固定 SQL 的已编译语句，减少重复编译开销。五个版本均使用同一实现；没有放松 FULL-WAL 提交、复制字节校验或计数语义。故不能把这项公共优化单独归因于某项消融收益。

Full 两轮远端读取为 102 / 100 MiB，低于 NoHotspot 的 122 / 122、NoAffinity 的 150 / 150、NoJoint 的 132 / 132 和 SIEVE 的 104 / 104 MiB。Full 复制 45 / 44 次，低于 SIEVE 的 52 / 52 次。这些计数支持局部决策改善了整体数据路径的解释；实际收益以上表墙钟速率为准。

## 实验定义与验证范围

- 前三张表均为完整方案对比只关闭对应模块的版本，分别回答热点估值、跨逻辑域亲和放置、联合准入是否具有边际收益；第四张表才是完整方案对比共享 SIEVE。配置一致性由独立审计核对。
- 有效速率为逻辑读取字节数除以实测任务墙钟时间；合并速率为两轮总字节除以总时间，未对各轮速率作简单平均。异步任务排空后的速率也在表中报告，两轮四项均正向。
- 运行于 cn7，远端为 cn13 经 NVMe/TCP 提供的存储，O_DIRECT，3 个串行发请求的逻辑消费域。并非真实多 GPU 并行执行、NVLink 或端到端推理性能证据。
- 每轮每版本 576 次读取，单次 2 MiB；10 次测速合计 5,760 次读取。同一冻结源码及二进制、同一输入、容量和 I/O 路径；第二轮版本顺序与第一轮完全相反。
- cn7 的 10 个原生测试目标及 126 项 Python 测试通过；另有 5 个版本共 480 次逐请求 SHA256 内容校验全部通过，内容校验运行不用于测速结论。
- 独立复核核对 97 个冻结源文件、全部测速请求、源文件及二进制身份、SQLite 与 JSON 计数、缓存容量、复制次数、内容校验次数及单开关消融。负向审计测试能够拒绝伪造的开销样本计数及吞吐增益。

## 尚不能据此得出的结论

第二轮 Full 相对 NoAffinity、NoJoint、SIEVE 的 p99 分别增加 2.143%、2.601%、0.730%，所以不能宣称所有性能指标均达标。正值 p99 变化表示变慢，负值表示改善。本次没有将原严格判定失败改成通过。

这两轮使用同一个已参与调试的移动热点输入，尚无独立输入、足够重复次数或置信区间支持普遍优势。固定热点仍定位为稳定负载基准，均匀随机为不可预测性边界，但本次最终二进制未重测这两类负载，不能沿用旧版本结果证明新版本无回退。三项消融支持各模块在当前输入中的边际作用，不能单凭此证明论文创新性、统计显著性或真实多 GPU 收益。下一步若扩大验证，应冻结当前版本与参数后采用未参与调参的输入；本次不自行扩大实验规模。
