SubmitBackground currently performs an additional synchronous FULL-WAL update of background_submitted on the foreground path. Completion and other telemetry already share a batched fence. The opt-in change defers only the submission statistic into that existing fence. It does not defer authoritative read counts, cache-state transactions, copy verification or source identity checks. It applies identically to Full, H/P/J ablations and shared SIEVE. SyncSubmission disables only defer_background_submission_metrics and is a separate implementation control.

Correctness prerequisites: no durable completion may overtake its submitted count; accepted queue items and submission deltas must agree; thrown tasks and failed SQLite transactions must preserve error/completion telemetry exactly once for retry; rejected/unknown/duplicate releases must not create successful work. Default-off retains the old submission protocol. Each valid readonly Release now publishes read_release_count only after its possible fallback submission. A drain observation requires all expected releases and equal submitted/completed counts in one SQLite snapshot. The drain timer includes waiting for that fence. This is necessary because old equal counters can otherwise hide a new in-memory submission. Both enabled and disabled controls use the new release fence; old archived configurations remain supported.
