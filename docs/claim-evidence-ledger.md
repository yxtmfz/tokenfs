# 论文主张、缺口与验收对应表

依据为本仓库 README、system-design.md、model-and-controller.md、experiments.md，不假设另有未提供的论文内容。验证允许否定原主张；未支持的主张必须收窄或删除，不能以命中率替代速度收益。

## 本轮消融对象

| 文档主张 | 真实对照 | 触发条件/必要证据 | 当前可评价范围 |
|---|---|---|---|
| 整体策略减少访问代价 | AURA-core vs RemoteOnly、LRU-equal、LFU-equal | 相同 trace、字节、配额；完整 wall 与 MiB/s；配对区间/检验 | cn7→cn13 单客户端存储 replay |
| 价值淘汰优于通用淘汰 | core vs no-value | 两者都能复制；实际发生 EVICT；只换 victim 规则 | C++ 当前 value_aware 启发式，不等于完整 EvictionLoss |
| 共享需求驱动放置更好 | core vs no-affinity；另列 no-xgpu | 前者保留跨域复制，后者关闭架构功能；检查副本动作与真实提速 | 三个逻辑域，同一主机/磁盘 |
| 联合决策好于各自决策 | 四格 E0A0/E1A0/E0A1/E1A1 | 交互时间项及区间 | 仅价值×亲和交互；不是完整 independent-vs-RobustBenefit |
| 趋势预测降低错误放置 | core vs no-trend | 热点迁移与稳定反例；策略动作有变化且提速 | C++ 长短窗口，不代表所有 Python 估计器 |
| 收益准入避免无效搬运 | core vs no-gain | 随机/稳定两面；复制 payload、wall、MiB/s | 当前固定代价参数，非在线校准模型 |
| 预取收益 | prefetch vs core | 顺序和均匀随机都报告，包含后台收尾 | 文件编号预测，非真实模型语义预测 |
| 后台化改善前台速度 | core vs synchronous | 同复制串行度/校验规则，前台及含 drain 时间都报告 | 不能称零前台开销或无资源争用 |
| 复制/元数据正确性 | 全内容校验、计数、并发读、重启 | 原始请求与缓存哈希一致，canonical 不变 | 只读不可变对象；并非任意写并发/断电保证 |

LRU-equal/LFU-equal 的基础准入为同一 read-through 门槛2次、同一异步复制能力、同一每域配额；它们并不代表所有 LRU/LFU 实现或调参后的最强现代缓存。需要评价准入时使用 no-gain，而非把整套准入与淘汰一起关闭。

## 已修复的问题与证据

| 缺陷 | 修复 | 验证 |

| 跨域副本不在普通淘汰池，基线复制能力不同 | 同一复制路径、同一候选池与容量规则 | 三域压力读校验与 policy-events |

| 统计快照尚未落盘就判丢字节 | 批量事务、请求计数/字节结算后读取 | 旧失败保留；随后 correctness-03/04 全通过 |
| 复制改布局时覆盖新访问/亲和元数据 | 布局字段定向提交；复制完整校验后 READY | 全内容与并发读验收 |

| 各阶段相加冒充总耗时 | 外层 monotonic wall；同逻辑字节求 MiB/s | 审计重新计算 throughput 恒等式 |
| 清页缓存失败仍继续 | 旧入口失败即退出；新入口不清全局缓存 | 当前明确双层前台 O_DIRECT 与目标缓存边界 |
| 重用结果目录覆盖旧证据 | 新目录必须不存在；每次记录版本/二进制/trace/config | 整批审计与归档 hash |
| 满容量 SWAP 没有临时空间却生成计划 | 拒绝不可执行计划，单批预留预算并去重 | 保留旧副本、容量/SLO/带宽门槛回归 |

## 仍不能用本轮结果补齐的部分

1. **理论模型与真实实现之间的断层。** C++ 的价值函数将访问计数约在5次后饱和，使用固定重计算/远端代价代理；Python 的需求区间、布局差分收益和资源价格尚未完整执行于 FUSE。解决路径是统一一个可执行决策接口，输出带 layout_version 的动作，并对同一 snapshot 对照公式与实际动作。接入后才能进行 no-uncertainty、independent、完整 joint 的真实速率消融。增加同名但无实际行为的开关无效。
2. **满容量强 SWAP 与崩溃恢复。** 先复制后删除在物理空间完全满时无法凭空成立。需要显式 staging 配额，事务预留预算，COPYING/VERIFYING/READY/EVICTING 持久状态；在临时写、校验、rename、元数据提交、旧副本删除每个点中断并恢复。总预算要包含 staging，所有基线相同。当前拒绝不可执行计划解决了错误调度，尚未实现这一整套强保证。
3. **物理峰值占用。** 已打开后被 unlink 的文件仍占磁盘，目录遍历只看到最终可见占用；本轮只检查最终配额。若宣称严格峰值上限，需要 fd 引用计数/延迟回收和磁盘实际分配量采样，不能用最终目录大小证明。
4. **负载与硬件外推。** 合成单请求流不能证明生产 trace、并发扩展、多物理 GPU 或真实推理 TTFT。需真实匿名访问轨迹及推理集成，在相同模型、请求、精度和输出质量下比较 tokens/s、TTFT、端到端耗时。本轮不会把存储 MiB/s 改名为推理收益。
5. **硬件和缓存边界。** 当前客户端和目标后端都在既有文件系统/loop 路径上，目标缓存与其他任务不受控。独立 namespace 保证数据隔离，不保证独占设备性能。裸 NVMe、两端冷缓存、链路上限、带宽竞争和多客户端结论必须另测。
6. **敏感性与最强基线。** 正式批次固定每域8 MiB；mixed 的16 MiB对象本来不能进缓存。因此不能把它单独当作纯大小感知淘汰证明。容量比、对象均可入缓存的变长实验、长持续稳态、后台带宽上限、TinyLFU/S3-FIFO等基线仍需后续预先固定的新批次。
7. **小效应与统计功效。** n=10不能保证检测1%以内的收益，经验请求p99也只有每次96条请求。无显著差异不是已证等效；不能因差一点显著不断追加样本。后续样本量必须依据事先规定的最小实际收益和 pilot 方差确定，使用新的保留种子/trace。
8. **价值模型各项尚未被单独识别。** 当前对象的远端/重计算代价元数据使用固定默认值；no-value 只替换整个 victim 规则。因此即使它提速，也不能推出“重计算成本项、来源成本项、大小项分别有效”。需新增同频不同实测服务成本、同成本不同大小且均能入缓存的负载，逐项关闭模型项；成本来自实际执行计时，不能给对象手填一个高成本后再把模拟分数当速度证据。
9. **逻辑亲和与实际设备亲和不同。** 三个逻辑域位于同一客户端磁盘，owner-local 与 caller-local 没有真实 PCIe/NVLink/跨机 Peer 的路径差异。no-xgpu 的变化还涉及可利用缓存域和副本数，不能解释为纯亲和算法贡献；纯放置对照应使用保留架构能力的 no-affinity，并把结论限定在当前逻辑域设置。
10. **防抖动未被本批检验。** 本批冷却与最短驻留为0，不能据此验证文档中的防抖机制。该主张需要稳定、交替迁移、噪声三个类别的长期 trace，持续时间覆盖多个冷却窗口，对照只关闭防抖项，并同时报告真实速度和副本反复搬运量。

## 最终可行的论文收口方式

本轮先完成真实可执行部分的公平检验和原始证据归档。所有性能叙述使用真实 wall/MiB/s、适用场景、区间和反例；组件没有速度收益就不写成已验证创新贡献。文档中的完整统一模型与强一致性保留为设计/待验证，不混入 C++ 已完成列表。

若论文必须保留完整联合、鲁棒区间或真实推理贡献，则以上对应实现和独立实验是必要工作，不能仅靠重新画图达到“全部验证”。后续算法改进须另设开发集和冻结测试集；本轮正式结果一旦查看，即不再作为新算法的未知测试集。

## formal-02 最终验收

400/400 正式运行通过整批审计；cn7 Release 72/72 全内容校验，cn8 独立72/72校验通过。正式测量的代码冻结在67d219d，后续日志修复不改写该批版本。

- 整体对等主比较10项，2项支持提速（稳定/迁移对 LRU），其余8项不确定；没有确立相对 LFU 优势。
- 均匀随机相对 RemoteOnly 耗时增加9.19%，属于必须保留的负结果。
- 价值淘汰仅稳定热点得到支持；亲和只在随机下有小幅支持；异步两场景支持；趋势无确定收益。
- no-gain 所测稳定/随机场景没有实际收益准入拒绝，不能识别筛选机制收益；后续必须使接受/拒绝边界均被覆盖。
- 预取顺序耗时降低1.55%，随机增加6.15%；四格实验未支持有利协同。
- 最终事件复核另发现负 value score 的日志转换错误，已修复并回归。排序一直使用独立 int64，原始记录不改写；formal-02 的 score 不用于模型项分析。

完整速度、区间、失败记录索引与后续工作见 [cn7 实测报告](../reports/latest/paper-experiments/10_real_cn7_evidence/README.md)。本轮结论是有限场景的真实收益，不是全部理论主张成立。
