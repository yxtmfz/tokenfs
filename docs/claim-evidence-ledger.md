## 第一轮结束时的缺口（第二轮进展见文末）

1. **理论模型与真实实现之间的断层。** C++ 的价值函数将访问计数约在5次后饱和，使用固定重计算/远端代价代理；Python 的需求区间、布局差分收益和资源价格尚未完整执行于 FUSE。解决路径是统一一个可执行决策接口，输出带 layout_version 的动作，并对同一 snapshot 对照公式与实际动作。接入后才能进行 no-uncertainty、independent、完整 joint 的真实速率消融。增加同名但无实际行为的开关无效。
2. **满容量强 SWAP 与崩溃恢复。** 先复制后删除在物理空间完全满时无法凭空成立。需要显式 staging 配额，事务预留预算，COPYING/VERIFYING/READY/EVICTING 持久状态；在临时写、校验、rename、元数据提交、旧副本删除每个点中断并恢复。总预算要包含 staging，所有基线相同。当前拒绝不可执行计划解决了错误调度，尚未实现这一整套强保证。
3. **物理峰值占用。** 已打开后被 unlink 的文件仍占磁盘，目录遍历只看到最终可见占用；本轮只检查最终配额。若宣称严格峰值上限，需要 fd 引用计数/延迟回收和磁盘实际分配量采样，不能用最终目录大小证明。
4. **负载与硬件外推。** 合成单请求流不能证明生产 trace、并发扩展、多物理 GPU 或真实推理 TTFT。需真实匿名访问轨迹及推理集成，在相同模型、请求、精度和输出质量下比较 tokens/s、TTFT、端到端耗时。本轮不会把存储 MiB/s 改名为推理收益。
5. **硬件和缓存边界。** 当前客户端和目标后端都在既有文件系统/loop 路径上，目标缓存与其他任务不受控。独立 namespace 保证数据隔离，不保证独占设备性能。裸 NVMe、两端冷缓存、链路上限、带宽竞争和多客户端结论必须另测。
6. **敏感性与最强基线。** 正式批次固定每域8 MiB；mixed 的16 MiB对象本来不能进缓存。因此不能把它单独当作纯大小感知淘汰证明。容量比、对象均可入缓存的变长实验、长持续稳态、后台带宽上限、TinyLFU/S3-FIFO等基线仍需后续预先固定的新批次。
7. **小效应与统计功效。** n=10不能保证检测1%以内的收益，经验请求p99也只有每次96条请求。无显著差异不是已证等效；不能因差一点显著不断追加样本。后续样本量必须依据事先规定的最小实际收益和 pilot 方差确定，使用新的保留种子/trace。
8. **价值模型各项尚未被单独识别。** 当前对象的远端/重计算代价元数据使用固定默认值；no-value 只替换整个 victim 规则。因此即使它提速，也不能推出“重计算成本项、来源成本项、大小项分别有效”。需新增同频不同实测服务成本、同成本不同大小且均能入缓存的负载，逐项关闭模型项；成本来自实际执行计时，不能给对象手填一个高成本后再把模拟分数当速度证据。
9. **逻辑亲和与实际设备亲和不同。** 三个逻辑域位于同一客户端磁盘，owner-local 与 caller-local 没有真实 PCIe/NVLink/跨机 Peer 的路径差异。no-xgpu 的变化还涉及可利用缓存域和副本数，不能解释为纯亲和算法贡献；纯放置对照应使用保留架构能力的 no-affinity，并把结论限定在当前逻辑域设置。
10. **防抖动未被本批检验。** 本批冷却与最短驻留为0，不能据此验证文档中的防抖机制。该主张需要稳定、交替迁移、噪声三个类别的长期 trace，持续时间覆盖多个冷却窗口，对照只关闭防抖项，并同时报告真实速度和副本反复搬运量。

## 第一轮确定的论文收口原则

本轮先完成真实可执行部分的公平检验和原始证据归档。所有性能叙述使用真实 wall/MiB/s、适用场景、区间和反例；组件没有速度收益就不写成已验证创新贡献。文档中的完整统一模型与强一致性保留为设计/待验证，不混入 C++ 已完成列表。
