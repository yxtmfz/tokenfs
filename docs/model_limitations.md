# AURA-KV 模型局限

## 1. 需求估计局限

Gamma-Poisson 和 EWMA 只能利用历史访问统计。突发事件、业务阶段切换、调度策略变化和未来任务分布变化都可能让估计偏离真实需求。系统通过创建用需求下界、删除用需求上界来降低风险，但这不是理论最优保证。

## 2. 来源代价局限

当前代码能分解本地、peer、远端和重算来源代价，但真实环境中的 NVMe-oF 队列深度、TCP 重传、RDMA 拥塞、GPU copy engine 竞争和 NUMA 影响尚未完整接入。缺失项不能默认当作真实为 0，真实部署时应通过 metrics 更新。

## 3. 布局收益局限

`EvictionLoss`、`ReplicaGain` 和 `RobustBenefit` 是在线布局决策的代理目标，单位是累计毫秒。它能解释“布局改变后获取缓存的预计服务代价变化”，但不能直接等同于 TTFT P99、吞吐量或端到端请求时延。

## 4. 模拟器局限

小规模穷举只能验证在线算法与最优布局之间的差距，不是完整理论最优证明。模拟结果必须标记 `SIMULATED RESULT`，不能伪装成真实硬件实验。

## 5. 当前工程局限

AURA-KV 策略已经有需求估计、代价模型和布局收益原型；完整后台执行器、decision_log 持久化、并发预算预留和真实 vLLM/SGLang 接口仍需在真实环境前后继续补齐。
