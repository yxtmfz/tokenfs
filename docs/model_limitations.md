# 模型局限

本文说明当前系统和模型不能过度解释的地方。

## 1. 性能结果局限

当前目录模拟环境不能代表真实 NVMe-oF：

- 没有真实网络 RTT。
- 没有真实 NVMe/TCP 队列。
- 没有真实 SSD 控制器行为。
- 可能受到 Linux 页缓存和虚拟磁盘影响。

因此当前性能结果只能作为开发验证，不能作为论文最终性能结论。

## 2. 需求预测局限

需求估计基于历史访问，无法准确预测：

- 突发热点。
- 新任务首次访问。
- 业务侧 prompt 分布突然变化。
- 模型调度器迁移任务导致的访问变化。

当前使用下界/上界和防抖动降低误判风险，但不能消除误判。

## 3. 代价模型局限

代价模型目前是可解释启发式，不是全局最优求解器。

受限点：

- 真实网络拥塞未接入。
- 真实 GPU H2D 和反序列化代价未测量。
- 多动作 SWAP 尚未完整实现。
- Shadow price 和在线调参仍是计划。

## 4. 系统一致性局限

TokenFS 已有临时文件、SQLite WAL、checksum 和恢复扫描，但仍不是完整生产级分布式文件系统。

尚缺：

- 多节点元数据服务。
- 分布式锁或租约服务。
- 完整后台任务 WAL。
- 真实断电级恢复验证。

## 5. GPU 集成局限

当前通过路径和环境变量识别 GPU：

```text
TOKENFS_GPU_ID
CUDA_VISIBLE_DEVICES
/gpu0, /gpu1 ...
```

真实 vLLM/SGLang 集成需要进一步接入实际 KV Cache 生命周期和 trace。

## 6. 共享判断局限

共享必须由安全键判断。若模型版本、tokenizer、位置编码、dtype 或并行配置不同，即使 prompt 文本相似也不能共享。

当前仓库保留共享安全抽象，但没有实现完整生产级 KV Tensor 内容寻址系统。
