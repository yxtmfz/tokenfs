# 02. 背景与问题定义

## 1. LLM 推理中的几个基础概念

Prompt 是用户输入给大模型的文本。Tokenizer 会把 Prompt 切成 Token，模型实际处理的是 Token 序列。

推理分为两个主要阶段：

- Prefill：一次性处理输入 Prompt，计算每一层注意力需要的 Key/Value。
- Decode：逐个生成新 Token，并复用历史 Key/Value。

KV Cache 是 Transformer 模型注意力层产生的 Key/Value 张量缓存。保存 KV Cache 可以避免重复 prefill，尤其适用于公共系统提示词、长文档前缀、多轮对话和 Agent 模板。

## 2. 为什么需要本地 SSD 和远端 NVMe-oF

可以把几类存储看作不同距离的柜子：

| 层级 | 特点 | 在本项目中的角色 |
|---|---|---|
| GPU 显存 | 最快、最贵、容量最小 | 活跃推理数据，不由 TokenFS 直接管理 |
| CPU 内存 | 快、容量较大 | 可作为后续优化层，当前不是重点 |
| 本地 SSD | 延迟低、容量有限 | GPU 节点附近的热点缓存层 |
| 远端 NVMe-oF SSD | 容量大、可共享、有网络长尾 | 权威副本和冷数据容量层 |

NVMe-oF 是 NVMe over Fabrics，通过 TCP 或 RDMA 网络访问远端 NVMe 存储。TokenFS 当前不在代码里直接实现 NVMe 协议，而是通过脚本把远端 Namespace 挂载为目录，再由文件系统和策略层访问该目录。

## 3. 问题定义

给定：

- 缓存对象集合 `K`；
- 计算节点集合 `M`；
- 每个节点的本地 SSD 容量；
- 远端 NVMe-oF 权威存储；
- 请求流和访问事件；
- 容量、重复副本、带宽和 SLO 约束。

系统在线选择：

```text
KEEP / PROMOTE / REPLICATE / DEMOTE / EVICT_LOCAL / PIN / PREFETCH
```

目标是在安全约束下减少：

- 远端读取量；
- 重计算时间；
- 前台获取 KV Cache 的累计服务代价；
- P95/P99 长尾风险；
- 重复副本空间；
- 副本 churn；
- 后台迁移对前台请求的干扰。

## 4. 为什么简单策略不够

| 策略 | 问题 |
|---|---|
| RemoteOnly | 容量充足但本地命中率为 0，远端长尾影响 P99 |
| ProducerLocal | 谁产生谁本地保存，跨节点共享时其他节点仍读远端 |
| LRU | 只看最近访问时间，可能误删重算很贵的公共前缀 |
| LFU | 只看累计次数，对热点迁移反应慢 |
| StaticNReplica | 固定副本数无法适配容量压力和共享强度 |
| WeightedScoreBaseline | 人工权重缺少统一单位，容易重复计算同一因素 |

本项目使用代价模型来替代人工权重，把“访问次数”和“访问代价”统一换算成未来累计毫秒。

## 5. 非目标

- 不声称当前模拟结果是真实硬件性能；
- 不直接等同代理服务代价和真实 TTFT P99；
- 不在没有真实环境时声称最终性能提升；
- 不把 Planned 功能写成已经可运行功能；
- 不声称全球首创或保证论文级结论。
