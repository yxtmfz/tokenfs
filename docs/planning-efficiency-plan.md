# 规划开销优化：新验收标准与固定12组回归

用户在第30轮完成后明确取消5%幅度门槛。本轮预先采用positive-throughput-v2：实际前台吞吐严格提高（>0），后台排空后吞吐不退化，p99不退化；正确性/计数审计、容量及暂存上限必须通过，组件比较还需机制实际触发且执行动作改变。零增益不算提速。小于噪声的正值只能称本次观测提升，不能称统计确认。

历史5%判断不修改。第30轮在新标准下另行解释：6/9比较通过，仍有迁移热点Full/Independent、固定热点Full/SIEVE、迁移热点Full/SIEVE三项实际退化。CPU、复制量和远端字节是解释开销的指标，资源硬约束是24MiB磁盘与4MiB暂存；不要求每个解释性计数都同时下降来代替真实吞吐。

候选efficient_measured_planning默认关闭，不改变策略目标和准入门槛：

- 滑动窗口的相邻重复次数及碰撞对数随插入/移出增量维护，替代每次Observe扫描整个窗口。
- 同一次受害者排序，价值只计算一次，保留原浮点操作、recency与key的打破平局顺序。
- 保留原实现作为对照路径。12,000步确定性测试覆盖窗口变化、独立/联合、私域/共享、成本开关、排序开关，逐步比较全部决策值、选中受害者和排序。

这是实现开销优化，不是新算法创新；不能承诺它解决第30轮所有负结果。当前暂存读取寿命仍随后台复制结束，存在内存服务与复制时序耦合；此次不改变暂存容量、可见性或生命周期，以免在没有对照的情况下叠加机制。

固定12组沿用第30轮已知回归输入3271/3272/3273、顺序及4个版本Full/CallerOnly/Independent/PoolSIEVE1。三种控制器均启用新选项，SIEVE不运行MeasuredPolicy。所有版本相同共享读取、24MiB总磁盘与4MiB暂存；三个控制器8/8/8MiB、SIEVE24/0/0MiB。Full/CallerOnly和Full/Independent仍只差各自目标开关。

每组576×2MiB。使用同一新Release程序、cn7→既有cn13 NVMe/TCP，仅12次，不访问cn14、不改磁盘。完整保留失败，不以失败为由追加、换种子或改阈值；不扩大样本。运行前冻结源码/配置/程序，之后独立复核原始数据。

这批没有同批关闭efficient_measured_planning的Full，因此不能量化优化相对旧实现的独立端到端增益，也不能跨批计算提速归因。它检验新候选是否解决已知场景的当前组件与系统比较。每条件仍只有一组，不能当作独立确认；没有no-hotspot和物理GPU实验。若观察到负结果，如实报告，不声称全部达标。
