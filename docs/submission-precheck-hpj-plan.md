# Submission precheck development protocol (79)

This candidate addresses wasted control work, not a new hotspot forecasting contribution. In the retained 77 public input, 934 of 967 submitted Full tasks ended without a gain, including 897 rejected before a resident snapshot. Moving Full and NoHotspot had equal remote traffic and copy counts; tiny speed differences there do not establish a causal hotspot benefit. The 78 frozen batch is preserved independently.

The default-off `precheck_shared_submission` candidate may avoid queuing an unprofitable measured shared-placement attempt at the current observation. It must use each arm's existing options and every permitted destination. Lock contention, unavailable or ambiguous capacity evidence and unsupported configurations fall back to the existing submission path. It never turns a rejected advisory plan into permission to copy; execution retains the live admission/capacity checks. Every subsequent read may reconsider the object. This changes when evidence is evaluated: a skipped submission is not guaranteed equivalent to a queued task that could observe later requests or cost samples. SIEVE retains its own admission semantics and never uses the measured-profit gate.

The development protocol preserves the inspected inputs `moving_shared-74801` and `public_toolagent-74802`, 1,152 requests of 2 MiB, total disk quota 24 MiB and retained RAM 4 MiB. Six arms are Full, NoHotspot, NoAffinity, NoJoint, PoolSIEVE1 and NoSubmitPrecheck. The last arm disables only the new precheck; all arms retain the 78 submission-metric fence and release accounting. Two rounds reverse a predetermined per-input order, for 24 speed runs and 576 separate request-content checks. No mid-batch tuning, hashing or diagnostic tracing during speed runs, and no performance-based repetition of the same frozen candidate.

Freeze source, Release binary, complete configurations, trace/object hashes and order before launch. All arms use the same binary and storage path. Before timing, native tests must exercise lock contention, headroom, low/high value, ablation options, duplicate/ambiguous metadata and the disabled path. After timing, independently recompute actual logical-byte throughput and whole-request nearest-rank p99, verify the final readonly-release count and durable submission/completion equality, and retain full background-drain time, all I/O, copies and precheck counters.

Primary acceptance remains all 16 same-round Full/NoHotspot, Full/NoAffinity, Full/NoJoint and Full/PoolSIEVE1 comparisons: strictly positive throughput gain, strictly lower response p99, no drain-throughput regression and active changed mechanisms for the ablations. The four NoSubmitPrecheck comparisons diagnose this implementation/policy-timing change separately; they cannot replace any failed primary comparison. Improved timing with unchanged H I/O does not by itself prove the H mechanism. These known-input, two-round tests are development evidence, not independent validation or statistical significance.

The environment remains serialized logical consumer domains on cn7 with cn13 NVMe/TCP storage. There is no physical-GPU or LLM-inference-throughput claim. Capacity or workload changes must be separately labeled sensitivity studies; they cannot replace a negative 24 MiB result.


All speed arms are restricted to the same CPU affinity set0,2,4,6 before any workload or TokenFS subprocess is launched; descendants inherit that mask. cn7 topology inspection identifies these as four distinct physical cores in package0, without sibling SMT threads in the mask. Before/after receipts record the mask per arm and the source audit rejects any change. This limits cross-socket scheduling variation seen as a potential confound when identical I/O coincided with large CPU-time differences in78; it does not eliminate governor, storage or other-host interference, and does not prove their causal role in78. The server governor remains its observed schedutil setting.79 is compared only within its own frozen batch; it is not a controlled before/after comparison to unpinned78.
