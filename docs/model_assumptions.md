# 模型假设

AURA-KV 的模型和模拟实验依赖以下假设。

## 1. 存储层级假设

- GPU 显存最快但容量最紧。
- GPU 节点本地 SSD 比远端 NVMe-oF SSD 延迟低。
- 远端 NVMe-oF SSD 容量更大，并可作为共享主副本层。
- 本地 SSD 适合作为热点缓存，而不是保存所有数据。

## 2. KV Cache 工作负载假设

- KV Cache 或 token shard 存在复用。
- 部分 prompt prefix 会被多个请求复用。
- 部分共享数据可能跨 GPU 访问。
- 大部分缓存块读多写少，适合缓存和复制。
- 数据可以用 `share_safe_key` 判断是否允许共享。

## 3. 需求估计假设

- 近期访问对未来访问有预测意义。
- 时间衰减窗口比纯累计访问更适合热点变化场景。
- 需求下界适合保守复制，需求上界适合保守删除。
- 模拟器中的 Oracle 只用于上限对比，真实系统不可获得。

## 4. 代价模型假设

- 获取代价可以分解为固定延迟、排队、传输、反序列化、格式转换和 H2D 代价。
- 不同来源的平均代价可通过配置或在线 metrics 估计。
- 在无真实硬件阶段，配置代价用于验证策略趋势，不作为真实性能数据。

## 5. 一致性假设

- 远端主副本是共享权威层。
- 本地副本是可删除缓存。
- 删除本地副本前必须存在替代来源。
- 未提交和校验失败的数据不能暴露给应用。

## 6. 实验假设

- 目录模拟可以验证功能和控制逻辑。
- trace-driven simulator 可以比较策略趋势。
- 真实 NVMe-oF 性能结论必须在真实硬件上复测。
