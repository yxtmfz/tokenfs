# Common read-path HPJ development (76)

Purpose: test whether two diagnosed common implementation costs obscure the existing hotspot, placement and joint-policy benefits. The H formula remains the retained report70 formula. Local model variants in report75 did not provide a consistent stronger candidate, and are not promoted. This is development on known inputs, not independent confirmation.

Frozen matrix: moving74801 and public74802, 1152 requests of 2 MiB each, two fully reversed rounds, six arms = 24 speed runs. Full, NoHotspot, NoAffinity, NoJoint, PoolSIEVE1 and NoRAMFirst all use one binary. First three primary comparisons disable only measured_static_reuse_value, shared_caller_only, or measured_joint_admission respectively. The overall comparison uses same-capability shared SIEVE. NoRAMFirst is an additional common-path control, not a fifth contribution.

All arms enable aligned-tail reuse. All except NoRAMFirst enable ram_first_routing. RAM-first routing validates and pins the existing canonical capture before querying disk replicas. A RAM hit does not claim a disk peer/replica hit, touch a disk replica, or set a disk SIEVE visited bit. Logical caller observations, durable read counts and source validation remain. This corrects a routing/accounting semantic discrepancy rather than merely changing metric names. HPJ compact planning still uses logical consumer access_order; it is not represented as a new physical-disk-recency estimator.

Disk quotas remain 24 MiB total, retained capture 4 MiB. Tail suffix payload is at most 4096 bytes per live non-RAM reader, independently reported, identically available to every arm. All requests, including first reads, contribute to actual wall throughput and response p99. No trace or correctness hashing during speed runs. Separate 96-request per-arm SHA sweep = 576 checks. Final local replica verification and backend/background/error accounting remain required.

Freeze source hashes, binary, input hashes, configuration, arm order and all runs. Primary pass requires each paired round to have strictly higher foreground throughput and lower request p99; full-background drain must not regress and the corresponding mechanism must be active. Report all comparisons internally; do not present a completed four-table success unless all comparisons pass. No positive-outcome reruns. A later candidate requires an identified mechanism change, and all earlier failures remain archived.
